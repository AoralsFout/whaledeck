# IPC 契约

> 本文是前端与 Rust 之间**命令名、参数、返回值、错误与事件**的唯一权威。
> 命令的内部算法见 [后端实现.md](后端实现.md)；数据形状见 [数据模型.md](数据模型.md)。

---

## 1. 调用约定

- 传输：Tauri 2 `invoke` / `listen`；前端统一封装在 `src/lib/ipc.ts` 的 `api` 对象。
- 参数名：JS 侧使用 camelCase（如 `gameId`），Tauri 自动映射到 Rust 的 snake_case 参数。
- 结构体字段：两侧都是 camelCase（Rust `#[serde(rename_all = "camelCase")]`）。
- 错误：Rust `Result<T, String>` 失败时 Promise reject，`String(err)` 即中文错误文案；前端不解析错误码。
- 取消：文件/保存对话框返回 `null`；`export_library` 返回 `false`；`import_library` 返回 `0`。
- 前端不得直接 `invoke("...")` 或拼接命令名；新增命令必须同时更新 `api`、本文件与 [后端实现.md](后端实现.md)。

## 2. 命令总表

### 2.1 游戏库

| 命令 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `list_games` | — | `Game[]` | 读取内存中的游戏库（启动时已从磁盘载入） |
| `save_game` | `game: Game` | `Game` | 新增或按 `id` 更新；返回后端确认后的完整记录 |
| `delete_game` | `id: string` | `boolean` | 移除记录；不存在返回 `false`；运行中报错 |
| `reset_playtime` | `id: string`、`sec: number` | `Game` | 覆盖累计时长（秒），返回快照 |

`save_game` 行为要点：

- `title` / `exePath` 为空 → 报错。
- `id` 为空 → 生成 UUID v4；`addedAt` 为 0 → 写入当前毫秒。
- `savePaths` 去空白、丢空项。
- 先写盘成功，再替换内存；失败时原列表不变。

### 2.2 启动与计时

| 命令 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `launch_game` | `id: string` | `LaunchResult` | 启动目标；进程目标创建会话并开始监控 |
| `get_sessions` | — | `Session[]` | 当前运行中的会话 |

`launch_game` 行为要点：

- 记录不存在 → 报错；同一 `gameId` 已在运行 → 报错。
- 启动失败：广播 `launch-failed` 并 reject。
- `pid === null`：用系统默认程序打开，不创建会话、不计时；仍更新 `lastPlayedAt`。
- `pid !== null`：写 `pending_session.json`、启动监控线程、更新 `lastPlayedAt`。

### 2.3 文件选择

| 命令 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `pick_entry` | — | `string \| null` | 选择任意文件（不过滤扩展名） |
| `pick_folder` | — | `string \| null` | 选择文件夹 |
| `pick_image` | `kind: "cover" \| "background" \| "icon"` | `string \| null` | 选择图片；过滤 png/jpg/jpeg/webp/gif/bmp；图标额外允许 ico |

### 2.4 扫描

| 命令 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `scan_folder` | `path: string` | `ScanEntry[]` | 递归扫描 exe；路径不是目录时报错 |

扫描上限与跳过目录见 [后端实现.md](后端实现.md) 扫描。

### 2.5 资源

| 命令 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `import_cover` | `id: string`、`src: string` | `string` | 复制独立草稿图片到 `covers/`，返回文件名；ID 校验同 `import_icon`，支持 PNG、JPG、JPEG、WebP、GIF、BMP；不改记录 |
| `import_icon` | `id: string`、`src: string` | `string` | 复制图标到 `icons/`，返回文件名；支持 `pick_image` 的图标格式；ID 仅允许 ASCII 字母、数字、连字符与下划线且非空；失败返回中文错误，不改记录 |
| `import_background` | `src: string` | `string` | 复制到 `backgrounds/`，同时保存设置，返回文件名 |
| `asset_path` | `kind: "cover" \| "background" \| "icon"`、`file: string` | `string` | 返回绝对路径；前端再经 `convertFileSrc` 展示 |

### 2.6 设置

| 命令 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `get_settings` | — | `Settings` | 读取当前设置 |
| `save_settings` | `settings: Settings` | `Settings` | 写盘并替换内存 |
| `set_close_behavior` | `behavior: "exit" \| "hide"` | `Settings` | 只更新关闭行为，写盘成功后返回完整设置；失败保持旧偏好 |
| `get_close_request` | — | `CloseRequest \| null` | 读取待确认关闭请求，补齐订阅前的请求 |
| `resolve_close_request` | `action: "hide" \| "exit" \| "cancel" \| "confirmExit"` | `CloseRequest \| null` | 按当前阶段处理；首次明确选择保存偏好；阶段不匹配时报错，失败保留请求 |
| `open_data_dir` | — | `void` | 用资源管理器打开数据根目录 |

### 2.7 存档备份

| 命令 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `backup_saves` | `id: string` | `SaveBackup` | 打包该游戏的存档目录 |
| `list_save_backups` | `id: string` | `SaveBackup[]` | 按时间倒序 |
| `restore_save_backup` | `id: string`、`file: string` | `number` | 还原并返回写入文件数 |
| `open_backups_dir` | `id: string` | `void` | 打开 `backups/<id>/`（不存在则创建） |

### 2.8 整库迁移

| 命令 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `export_library` | — | `boolean` | 弹保存对话框；取消返回 `false`；成功写 JSON + `.covers/` |
| `import_library` | — | `number` | 弹打开对话框；取消返回 `0`；成功整体替换并返回游戏数 |

导入是覆盖操作，不合并；格式见 [数据模型.md](数据模型.md) 导出文件。

### 2.9 联网补全

| 命令 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `search_meta` | `source: "bangumi" \| "vndb" \| "ymgal"`、`keyword: string` | `MetaItem[]` | 异步；联网检索 |
| `apply_meta` | `gameId: string`、`item: MetaItem` | `Game` | 下载封面并更新非空字段与来源 |
| `autofill` | `game: Game`、`field?: AutofillField \| null` | `AutofillResult` | 基于当前草稿生成本地候选，不写游戏库；省略 field 获取全部 |

`apply_meta` 行为要点：

- 有 `coverUrl` 时才下载；域名白名单、12MB 上限。
- 只写入非空的 `summary` / `developer` / `releaseDate`；`source` / `sourceId` 总是写入。
- 返回更新后的完整 `Game`，前端据此替换记录。

`autofill` 行为要点：

- 版本资源读不到时跳过，不影响图标/封面。
- 仅获取所选字段；名称、开发商、备注有非空候选即覆盖返回草稿的对应值，没有则保持输入值；图像结果写入独立资源文件，不覆盖或清理原资源。
- `filled` 是本次获取到的中文文本字段名（如 `["名称","开发商","备注"]`），`icon` / `cover` 表示图像候选是否生成；字段枚举见 [数据模型.md](数据模型.md) §2.5。
- 输入目标路径为空或不存在时返回可展示错误；允许未加入游戏库的新增草稿。确认后仍通过 `save_game` 保存。

## 3. 事件

| 事件 | 载荷 | 时机 | 前端处理 |
|---|---|---|---|
| `game-stopped` | `{ gameId, sessionSec, playtimeSec }` | 监控判定退出并完成结算后 | 移除会话、更新累计时长、Toast 本次分钟数 |
| `launch-failed` | `{ gameId, message }` | 启动抛错时（同时 reject 命令） | Toast 中文错误 |
| `settings-changed` | `Settings` | 首次关闭选择成功写入后 | 同步设置与排序，不重新载入游戏库 |
| `close-requested` | `CloseRequest \| null` | 待确认请求变化 | 显示对应自定义弹窗；空值关闭弹窗 |

事件由 Rust `Emitter` 广播；前端在 `App` 挂载时订阅，卸载时取消。事件不保证顺序，处理必须幂等（按 `gameId` 过滤）。

## 4. 前端封装映射

`src/lib/ipc.ts` 中的方法名与命令一一对应：

| 前端方法 | 命令 |
|---|---|
| `listGames` / `saveGame` / `deleteGame` | `list_games` / `save_game` / `delete_game` |
| `launchGame` / `getSessions` / `resetPlaytime` | `launch_game` / `get_sessions` / `reset_playtime` |
| `pickEntry` / `pickFolder` / `pickImage` | `pick_entry` / `pick_folder` / `pick_image` |
| `scanFolder` | `scan_folder` |
| `importCover` / `importIcon` / `importBackground` / `assetPath` | `import_cover` / `import_icon` / `import_background` / `asset_path` |
| `getSettings` / `saveSettings` / `openDataDir` | `get_settings` / `save_settings` / `open_data_dir` |
| `setCloseBehavior` | `set_close_behavior` |
| `getCloseRequest` / `resolveCloseRequest` | `get_close_request` / `resolve_close_request` |
| `backupSaves` / `listSaveBackups` / `restoreSaveBackup` / `openBackupsDir` | 同名 snake_case 命令 |
| `exportLibrary` / `importLibrary` | `export_library` / `import_library` |
| `searchMeta` / `applyMeta` / `autofill` | `search_meta` / `apply_meta` / `autofill` |

事件：`onGameStopped` / `onLaunchFailed` / `onSettingsChanged` / `onCloseRequested`。

## 5. 变更检查清单

新增或修改命令时：

- [ ] 在 `src-tauri/src/commands.rs` 或对应领域模块实现，并注册到 `lib.rs` 的 `generate_handler!`。
- [ ] Rust 模型加 `camelCase` 与默认值；`src/types.ts` 同步。
- [ ] `src/lib/ipc.ts` 加方法，组件不直接写命令名。
- [ ] 更新本文件的签名表与错误说明。
- [ ] 更新 [后端实现.md](后端实现.md) 的实现/限制（若有行为变化）。
- [ ] 若影响界面，更新 [前端实现.md](前端实现.md) / [界面与交互.md](界面与交互.md)。
- [ ] 在 [版本记录.md](版本记录.md) 记录行为变化。
- [ ] 至少补一个前端或 Rust 测试；命令层算法补单元测试。
