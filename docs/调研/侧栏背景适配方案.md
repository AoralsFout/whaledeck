# 侧栏背景分辨率适配方案

状态：已接入并完成本地测试，纳入本次源码交付；提交与验证记录见[版本记录](../版本记录.md)。选型核验日期：2026-10-23；接入验证日期：2026-10-24。

范围依据用户要求收窄为只调整图片尺寸和显示方式，不接入扩图、补图或生成画面模型；保留已有侧栏隐藏、半透明磨砂、自定义背景、透明度与封面来源规则。本文保留选型依据和实施路径；当前行为以[界面与交互](../界面与交互.md)为准，验证结果见[版本记录](../版本记录.md)。

## 1. 建议结论

本机候选实测后，已接入 Rust `fast_image_resize 6.1.0` 的 Lanczos3 做普通重采样，已有 `image` 继续负责解码和保存。设置中的开关、三种显示方式、取景与预览确认，以及关闭后的恢复行为，见界面文档 §4.3；后台边界与缓存见后端文档 §7.1。

原因：用户的目标是尺寸适配，不要求恢复低分辨率图片的细节。此次普通缩放库的效果相近，fast_image_resize 延迟更低；LIIF 在人工退化恢复样本中细节更好，但环境与推理成本更高。模型即使可以输出指定分辨率，也不能自动解决横图与窄竖侧栏之间的构图比例冲突。具体测试数字与限制见 [版本记录](../版本记录.md) 和本地实测报告。

## 2. GitHub 实际调研

通过 GitHub CLI 读取以下官方仓库的说明与元数据，并核对本项目依赖。后续已下载 LIIF 官方权重，在独立环境实际运行 LIIF、image 与 fast_image_resize；DIIF 因未找到官方预训练权重无法实测。下表记录能力和接入选择，实测方法见 §8，验证结果见版本记录与本地报告。

| 官方项目 | 核验到的能力与接入条件 | 本次选择 |
|---|---|---|
| [LIIF — yinboc/liif](https://github.com/yinboc/liif) | 任意分辨率图像表示；官方 demo 接受 `--resolution HEIGHT,WIDTH`；需要 Python、PyTorch 和模型权重。仓库代码 BSD-3-Clause；权重再分发条款需单独确认。 | 已实测官方 EDSR-baseline。适合另行评估低清图片预处理，本需求不作为即时适配默认项。 |
| [DIIF — HeZongyao/DIIF](https://github.com/HeZongyao/DIIF) | 任意倍率超分的官方 PyTorch 实现；仓库 Apache-2.0。任意倍率超分不等于自动调整构图，具体任意宽高接入还需验证。官方测试配置要求外部预训练权重，本次未找到可用官方下载。 | 未能实测，不参加质量排名，不使用随机权重替代。 |
| [image — image-rs/image](https://github.com/image-rs/image) | Rust 图片处理库，提供缩放和裁切；仓库为 MIT / Apache-2.0 双许可。本项目已有 `image 0.25` 依赖，质量档已调用 `resize_exact(..., Lanczos3)`。当前显式启用的解码格式只有 PNG。 | 0.25.10 已实测，继续承担图片读写等基础能力；支持背景的其他格式时补齐对应解码能力。 |
| [fast_image_resize — Cykooz/fast_image_resize](https://github.com/Cykooz/fast_image_resize) | Rust 缩放库，支持 SIMD、裁切及 Lanczos3 等滤波，MIT / Apache-2.0 双许可；官方也说明颜色空间处理需要调用方考虑。 | 本次尺寸适配首选，6.1.0 已独立 release 实测；接入前仍须核对最低 Rust 要求、透明像素和颜色处理。 |

来源为各仓库 README、Cargo.toml 和许可证；没有采用第三方性能排名，也不把仓库基准当成本项目耗时。实施时再次核对锁定版本：原有 image 0.25.10 需要 Rust 1.88.0，新接入 fast_image_resize 6.1.0 需要 1.87.0；本机使用 Rust 1.96 构建通过。项目清单仍声明 1.77.2，与既有锁定依赖要求不一致，此轮未改清单，也未验证 1.77.2 工具链兼容。

## 3. 分辨率与比例的区别

以下为尺寸计算示例，不是模型效果图。原图 1920×1080，侧栏显示区 258×820，DPR 为 1：

| 方式 | 处理 | 视觉结果 |
|---|---|---|
| 完整显示（建议默认） | 等比例缩放到约 258×145，放在 258×820 画布中央，空余处透出主题底色。 | 保留完整画面和人物比例，但上下留空。 |
| 铺满裁切 | 等比例缩放到约 1458×820，再取 258×820 区域；默认居中，可调水平和垂直取景位置。 | 不留空、不变形，但会裁掉大量左右内容；与当前 cover 同类效果。 |
| 拉伸铺满 | 直接重采样到 258×820。 | 保留整张图且铺满，人物会明显变窄；由用户主动选择。 |

不生成新画面时，比例不同的图片无法同时做到完整显示、不留空和不变形。提高像素数量也不会自动恢复原图缺失的真实细节。本次默认完整显示，是为了让适配开关与现有铺满裁切有可见差别。

## 4. 设置与预览

本地测试版已按以下设计接入「设置 → 外观 → 左侧栏」的背景选择区域，最终规格以界面文档为准：

1. 「侧栏背景适配」开关，旧设置缺省关闭，保留原有显示。关闭时仍保留用户上次选择的适配方式和取景位置。
2. 开启后显示三种方式：完整显示、铺满裁切、拉伸铺满；初始建议完整显示。
3. 铺满裁切提供水平 / 垂直取景位置和「恢复居中」；不用模型判断人物，不自动移动画面。
4. 显示原图尺寸、侧栏显示尺寸和目标像素尺寸，例如「显示区 258×820；目标 516×1640（2×）」；不要求用户手填固定分辨率。
5. 先展示与真实侧栏相同比例的预览，调整后点「应用」保存；「取消」丢弃本次适配草稿。开关和适配参数作为同一组草稿确认，避免浏览选项时直接改动实际背景。

只影响侧栏背景图片，主区布局、游戏封面文件和封面超分档位不变。图片来源沿用当前规则：自定义侧栏图优先；磨砂开启且未设自定义图时使用选中游戏封面。没有可用图片时提示先选图片，不更改原有无图回退效果。

## 5. 实现路径

### 5.1 测量与重采样

- 使用 `ResizeObserver` 测量侧栏背景可视区，不用整个窗口分辨率代替；同时响应 DPR / 缩放变化和窄屏导航尺寸变化。
- 目标物理像素：`round(侧栏 CSS 宽 × DPR)` × `round(侧栏 CSS 高 × DPR)`。保留合理的像素预算，防止极端窗口尺寸生成过大的图片；预算值在实现与实测时确定。
- 窗口拖动期间先缩放已有图；尺寸稳定约 200ms 后再生成，后台仅处理当前最新请求。生成期间保留上一张可用图，不清空、不闪白。
- 重采样在 Rust 后台工作任务执行，避免阻塞 UI；默认评估 Lanczos3 缩小效果，实际选择用本机 release 测试验证，不承诺未经测量的耗时。
- 磨砂扩边与适配画布一起设计：可视区尺寸与 blur 扩边尺寸分开，不能把适配图再当作 cover 放大裁切一次，导致完整显示失效。扩边仅复制已有边缘像素，不生成新画面。

### 5.2 缓存与异步正确性

- 原图只读，适配图存入独立缓存；不创建游戏版本备份，也不替换封面或背景源文件。
- 缓存键包含源图身份及内容版本、目标宽高、方式、取景位置和算法版本；不能只按文件名缓存，避免同名文件更新后显示旧图。
- 同参数复用结果；窗口尺寸请求合并，旧任务结果不得覆盖新选择、已关闭的开关或新游戏的背景。
- 生成失败保留原图显示并提示可重试，不修改用户的图片引用。缓存有容量上限，旧尺寸可清理，避免拖动窗口长期积累文件。
- 本期不在滚动、设置打开、鼠标呼出侧栏时做重采样，不重复解码列表图标，保留刚完成的渲染隔离。

### 5.3 改动范围与顺序

本地接入已完成以下步骤：

1. 更新数据模型、接口、前后端及界面权威文档；新增适配开关、方式、取景参数，旧设置默认关闭。
2. 实现独立的图片尺寸计算、重采样、缓存与请求版本保护；继续复用现有图片导入和资源加载边界。
3. 接入侧栏尺寸测量、设置草稿和预览确认，验证不与磨砂扩边重复缩放。
4. 本地运行并给用户查看，不提交、不推送；用户确认后再决定后续动作。

## 6. 验收与待验证项

- 横图、竖图、方图分别检查三种模式；完整显示保留画面，裁切可调取景，拉伸与说明一致。
- 258px 桌面侧栏、375px 窄屏导航、不同窗口高度、100% / 150% / 200% 缩放，目标像素与实际区域对应。
- 磨砂开 / 关、自动隐藏开 / 关、自定义图 / 游戏封面、透明度 0 / 50 / 100、深色 / 浅色组合均保留。
- 关闭适配恢复原有 cover 效果；取消草稿不改变实际侧栏；确认后重启保留；旧设置可正常读取。
- 快速切游戏、换图、关开关、连续缩放窗口，不闪白、不显示迟到旧结果，不更改原图。
- 验证 PNG / JPEG / WebP 等实际支持格式、损坏图片、超大源图、透明图片与缓存清理。解码像素限制在解码前设置，不只限制输出尺寸。
- 性能用 release 实测设置打开、滚动、拖动窗口及切图；记录耗时、缓存命中、峰值内存。没有实测前不写“瞬间生成”或固定 FPS 保证。
- 执行 `pnpm build`、`pnpm test`；涉及 Rust 时执行 `cargo test`、`cargo fmt --check`，并完成桌面与窄屏手工回归。

## 8. 本机对照试验（已完成独立候选评估）

用户要求先实测候选并展示结果。本轮在独立试验目录中测试，不把试验依赖接入应用，也不修改用户游戏库。对 LIIF / DIIF 检查官方预训练权重可获得性；对可运行候选输出相同尺寸的真实图片，记录精确版本、输入、几何处理、设备、运行耗时与限制。普通缩放库不称为模型；不可用权重不得用随机权重或普通缩放冒充。

试验包含侧栏目标 258×820、516×1640，以及从高分辨率图降采样后恢复的同倍率清晰度对照。尺寸与构图分开评估；拉伸变形、完整显示留空和裁切损失均明确标注。耗时排除下载和环境安装，从已解码 CPU RGB 到输出 CPU RGB8；LIIF 计入 GPU 传输和同步，加载与首轮开销另记。CPU 与 GPU 结果用于本机方案选型，不作为相同硬件上的纯算法效率排名。

当前会话工作区 `outputs/背景适配实测/` 保存《实测报告.md》、真实 PNG、交互对照页、逐次耗时、恢复 PSNR 与环境哈希；复现脚本位于 `work/background-fit-benchmark/`。恢复分数只对应两张人工退化样本，不能作为通用画质结论。测试范围为 RGB 素材，透明图、其他解码格式、更多大图与应用运行时留待实际接入时验证。本轮验证与选型变化记录在 [版本记录](../版本记录.md)。
