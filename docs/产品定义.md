## 1. 定位

WhaleDeck（鲸鱼游戏台）是一个 **Windows 本地游戏 / 项目启动台**：

> 把散落在硬盘各处的游戏、软件、文档与文件夹收进一个界面，点一下就能打开；对以进程方式启动的目标，自动记录游玩时长。

它不联网也能完整使用；所有数据只保存在本机。

---

## 2. 要解决的问题

| 问题 | 对应能力 |
|---|---|
| 游戏装在不同盘符和目录，想玩时翻目录 | 任意路径加入、搜索、分类、收藏、排序 |
| 不知道自己玩了多久、上次什么时候玩 | 进程监控、自动计时、最近游玩、累计时长 |
| Steam / Epic / 独立 exe / 绿色版各自为政 | 统一入口；exe 可直接加入，启动器场景可用额外进程名 |
| 游戏目录里其实有封面，但没被利用 | 本地封面扫描 + 自动补全 |
| 存档散落、损坏后无法回滚 | 多存档目录、一键 zip 备份与还原 |
| 想换外观但不想装主题插件 | 预设主题、主色/强调色、背景图与遮罩 |

## 3. 目标与非目标

### 3.1 目标

1. 加入任意本地目标（exe、快捷方式、bat/cmd、文档、图片、文件夹）。
2. 一键打开，失败时给出可操作的中文原因。
3. 对进程目标自动计时，正常退出结算，异常退出可补算。
4. 数据只存本机，写入可靠、可备份、可迁移。
5. 外观可自定义并即时生效。
6. 不联网也能完成核心流程；联网只用于用户主动触发的元数据补全。

### 3.2 非目标

- 不做游戏下载、安装、更新、DRM、启动器替代。
- 不做云账号、多人共享、社交、排行榜。
- 不读游戏内存、不做作弊 / Mod 管理。
- 不做后台定时抓取、批量抓取或账号体系。
- 不承诺跨平台；当前只支持 Windows 10/11。

## 4. 用户故事与验收

| 编号 | 故事 | 产品验收 |
|---|---|---|
| U1 | 把任意程序 / 文件 / 文件夹加入库 | 选择后卡片/列表出现；标题默认取文件名（文件夹取目录名）；可手动改 |
| U2 | 给游戏配封面 | 选本地图片后复制进数据目录；列表缩略图与详情背景使用它；原图移动不影响 |
| U3 | 按分类找游戏 | 侧栏分类筛选；分类可来自游戏记录或设置页自定义 |
| U4 | 找上次玩过的游戏 | 默认「最近游玩」排序，收藏优先 |
| U5 | 知道一共玩了多久 | 详情显示最近游玩与累计时长；进程目标才统计 |
| U6 | 启动失败要知道原因 | 明确提示：路径不存在、工作目录不存在、无权限/启动失败、系统无关联程序 |
| U7 | 换电脑带走游戏库 | 导出 JSON + 封面目录；导入后恢复游戏与设置，导入前二次确认 |
| U8 | 换个喜欢的配色 | 预设/主色/强调色/背景图/明暗模式即时生效并持久化 |

> 界面级验收（尺寸、焦点、时序、窄屏）只在 [界面与交互.md](界面与交互.md) 定义。

## 5. 当前能力范围

| 能力 | 行为概要 | 详细规范 |
|---|---|---|
| 任意目标 | 进程目标按进程启动；其余用系统默认程序打开 | [后端实现.md](后端实现.md) 启动器 |
| 自动计时 | 每 2 秒采样，连续 3 次未命中判定退出；支持额外进程名 | [后端实现.md](后端实现.md) 监控 |
| 异常补算 | 启动写 `pending_session.json`，下次启动按时间差补算（上限 12 小时） | [数据模型.md](数据模型.md) 会话恢复 |
| 文件夹扫描 | 递归找 exe，默认上限 6 层 / 500 个，跳过系统与依赖目录 | [后端实现.md](后端实现.md) 扫描 |
| 批量加入 | 顺序写入；成功即时入库；首个失败即停；可重试剩余项 | [前端实现.md](前端实现.md) 批量加入 |
| 联网补全 | Bangumi / VNDB / 月幕；只读公开接口；用户点击才请求 | [后端实现.md](后端实现.md) 元数据 |
| 自动补全 | 读 exe 版本资源（名称/开发商/备注）+ 系统图标 + 本地封面 | [后端实现.md](后端实现.md) 自动补全 |
| 图像分层 | 封面 `coverFile` 与图标 `iconFile` 分开；主区只用封面 | [数据模型.md](数据模型.md) 字段 |
| 存档备份 | 多个存档目录打包为 zip；列表、还原、打开目录 | [后端实现.md](后端实现.md) 存档备份 |
| 可靠存储 | 原子写入、保留 5 份备份、损坏隔离并回退 | [数据模型.md](数据模型.md) 写入策略 |
| 主题 | 4 套预设、主/强调色、背景图、遮罩、明暗三档 | [界面与交互.md](界面与交互.md) 主题 |
| 迁移 | 导出/导入整个库与封面 | [数据模型.md](数据模型.md) 导出格式 |

### 5.1 需要联网的部分

只有「联网补全」会访问网络，且必须由用户在详情页打开对话框后主动搜索。自动补全、封面扫描、计时、备份全部离线完成。

## 6. 数据、隐私与合规

- 游戏库、设置、封面、图标、背景、备份都在本机数据目录，见 [数据模型.md](数据模型.md)。
- 不上传、不同步、不统计遥测。
- 联网补全只发送用户输入的关键词；不发送路径、时长或库内容。
- 外部图片只允许来自三家数据源图床，单张上限 12MB，见 [后端实现.md](后端实现.md) 图片下载。
- 数据来源与署名：
  - [Bangumi 番组计划](https://bgm.tv/)
  - [VNDB](https://vndb.org/)
  - [月幕 Galgame](https://www.ymgal.games/)
- 仅用于个人整理自己的游戏库，遵守各平台非商业使用条款；不做批量抓取、不定时同步。

## 7. 非功能要求

| 维度 | 要求 |
|---|---|
| 平台 | Windows 10/11，WebView2 运行时 |
| 窗口 | 默认 1280×820，最小 1000×640；无边框、透明圆角、自绘控制键 |
| 离线 | 除联网补全外全部可用 |
| 启动 | 窗口在数据、字体与首帧准备完成后才显示，避免白屏/闪烁 |
| 数据安全 | 原子写入 + 5 份备份 + 损坏回退；删除记录不动本地文件 |
| 可达性 | 键盘可操作、焦点可见、对话框焦点约束、尊重减少动态效果 |
| 语言 | 界面与错误提示使用简体中文 |
