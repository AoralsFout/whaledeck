## 2. 状态分层

### 2.1 全局状态：`useLibrary`

一个 Zustand store，持有游戏库、设置、运行会话、导航/搜索/排序、选中项、对话框开关、Toast 与所有动作。

**状态字段**

| 字段 | 说明 |
|---|---|
| `games` | 完整游戏库（含隐藏项） |
| `settings` | 设置；`null` 表示尚未加载 |
| `sessions` | 运行中的会话 |
| `ready` | 初次加载完成（成功或失败） |
| `busy` | 表单保存中 |
| `query` / `nav` / `sort` / `selectedId` | 视图状态 |
| `formOpen` / `editing` / `formAutofill` | 项目表单与自动获取入口标记 |
| `settingsOpen` / `scanOpen` / `metaOpen` | 其他对话框 |
| `toast` | 单条通知，3.4 秒后自动消失 |
| `superresProgress` | 当前详情派生的超分进度文案，由详情同步并在卸载时清理，展示规则见[界面与交互.md](界面与交互.md) §4.4 |

**初始化**

`init()` 并行执行 `listGames`、`getSettings`、`getSessions`，成功后写入 `games/settings/sessions`，并用 `settings.sort` 初始化排序。失败时仍把 `ready` 置真并 Toast，保证窗口不会永久隐藏。

**写入规则**

- 统一经过 `persistGame`：调用 `save_game`，**只接受后端返回的记录**，按 `id` 替换或追加。
- `saveGame`：`busy` 包裹；成功后关闭表单、清空 `editing`、选中保存项；若保存项不在当前筛选结果内，重置为「全部」或「已隐藏」并清空搜索。
- `toggleFavorite`：复用 `persistGame`，不关闭表单、不切换选择。
- `deleteGame`：成功后从列表移除；若删除的是当前项，`selectedId = null`，由视图规则回落到首项。
- `applyGame`：只替换已存在的记录（用于已持久化的元数据等返回），未知 `id` 忽略。
- 设置：`updateSettings` 先更新内存再保存，失败 Toast；`setSort` 也写设置，但失败静默（不打断排序）。

**启动与结算**

- `launchGame`：调用 `launch_game` 成功后才更新 `lastPlayedAt`；`pid` 非空时向 `sessions` 插入（先移除同游戏旧会话）；`pid` 为空时只提示「已用系统默认程序打开」。
- `handleStopped`：移除会话、用 `playtimeSec` 覆盖累计时长、Toast「本次游玩 N 分钟」（至少 1 分钟）。
- `handleLaunchFailed`：直接 Toast 错误。

**批量加入**

- `addScannedGames` 通过 `additionsQueue` **串行化**多个批次，避免并发重复写入。
- 每项按 `gamePathKey`（`trim`、`/`→`\`、小写）与当前 `games` 比较去重，因此同批次内已加入的项也会被后续项视为重复。
- 顺序写入；每成功一项立即更新库；遇到首个错误停止，`remaining` 为从失败项起的未加入项，`skipped` 记录跳过的重复项。
- 失败 Toast 包含「已加入 N 个 / 剩余 M 个 / 具体原因」；部分失败时扫描窗口保持打开，成功项变为「已在库中」。
- 空批次直接返回空结果，不发请求、不改通知。

**Toast**

- 全局单条；新 Toast 会清掉旧定时器；默认 3.4 秒；可手动关闭。

### 2.2 派生状态：`useLibraryView`

可见列表按 `games / nav / query / sort` 缓存；选择按可见列表与 `selectedId` 独立派生，切换游戏不重新筛选、排序：

1. `filterGames`：隐藏项只在 `hidden` 视图出现；`favorites` 只留收藏；`category` 精确匹配；搜索对 `title + category + tags` 做小写包含匹配。
2. `sortGames`：
   - `recent`（默认）：收藏优先，再按 `lastPlayedAt` 降序（`null` 视为 0）；
   - `title`：`localeCompare(..., "zh-Hans-CN")`；
   - `playtime`：累计秒数降序；
   - `added`：加入时间降序。
3. `selectVisibleGame`：当前 `selectedId` 仍在可见列表则保留，否则取首项，列表为空则 `null`；直接组合已缓存的筛选与排序结果。

`App` 在 `ready` 后把 `selectedId` 同步为派生结果，保证删除、筛选、搜索后详情不指向列表外。

### 2.3 对话框级 store

- **`createMetaSearch(initialKeyword, deps)`**：每次打开弹窗创建；内部 `version` 递增。
  - 有效提交（非空关键词）时 `request = ++version`；只有 `request === version` 才能写结果、结束加载、发空结果/错误通知。
  - 切换来源：清空结果、结束加载、使旧请求失效，不自动搜索；重复点当前来源不打断。
  - 编辑输入不触发搜索；关闭弹窗调用 `invalidate()`，迟到响应不再改状态。
- **`createSaveBackups(gameId, deps)`**：详情页按游戏创建；`lifetime` 标识生命周期。
  - `connect()` 重置状态并开始初始读取，返回清理函数；清理后所有迟到响应被丢弃。
  - `refresh` 用 `listRequest` 只接受最新一次列表读取，避免初始读取晚返回覆盖备份后的新列表。
  - 备份与还原共享 `busy`；还原只接受当前列表中已选中的文件；备份成功先接纳返回记录，再刷新列表；刷新失败保留已知记录与成功提示。
- **`createGameForm(initial, deps)`**：项目表单的独立草稿 store，职责与生命周期见 §3.2。
- **组件本地状态**：表单输入列表文本、保存/导入状态、详情展开、删除确认、时长修正、应用中等，均不进入全局 store。

## 3. 组件职责

| 组件 | 职责 | 关键行为 |
|---|---|---|
| `App` | 外壳与生命周期 | 初始化、事件订阅、默认选中、主题/背景、窗口显示、导航展开状态 |
| `Sidebar` | 导航、搜索、排序、列表 | 分类 chips、列表项、项目缩略图（回退规则见界面文档 §2.3）、双击启动、运行中圆点、收藏星标、底部计数 |
| `SidebarNavigation` | 侧栏呼出与收起 | 根据自动隐藏设置管理常驻或边缘悬停、延迟收起、焦点保留、断点切换和 Escape；隐藏时设置 inert，窄屏统一使用按钮导航 |
| `GameDetail` | 沉浸式详情 | 封面背景、标题/标签、悬停或点击展开详情、底部固定启动栏与统计栏、时长修正、复制路径、删除确认、自动补全、存档备份 |
| `GameForm` | 新增/编辑/补全确认 | 独立草稿、字段获取/恢复、名称/路径校验、图像预览、文件/目录选择与确认保存 |
| `SettingsPanel` | 设置 | 常规、外观、左侧栏、封面、分类、数据、关于标签页；关闭行为、主题、侧栏效果与背景、封面取景、分类、导出/导入、数据目录 |
| `SidebarBackgroundSettings` | 侧栏适配草稿 | 取景预览、分辨率显示、生成重试、应用与取消；生命周期见 §4.2.1 |
| `ScanDialog` | 扫描与批量加入 | 选目录、候选列表、已存在置灰、全选/反选、部分失败保留剩余选择 |
| `MetaDialog` | 联网补全 | 来源切换、搜索、结果列表、应用、无结果时手动选封面 |
| `Modal` | 对话框基础 | 原生 `<dialog>`、焦点约束、Escape、遮罩按下/抬起判定、焦点返回 |
| `ActionTooltips` | 操作栏提示 | 首次 1000ms、探索期 600ms、键盘聚焦立即显示、Escape/滚动/点击收起 |
| `Toast` | 全局通知与超分进度提示 | `role="status"`、有弹窗时挂到 `dialog[open]`；展示时序见[界面与交互.md](界面与交互.md) §4.4 |
| `EmptyState` | 空态 | 空库引导 / 筛选无结果 + 清除筛选 |
| `WindowChrome` | 无边框窗口 | 拖动区、最小化/最大化/关闭、监听最大化状态、非 Tauri 环境禁用 |

### 3.1 `GameDetail` 细节

- 详情外壳与内容区的生命周期分离，见 §4.2；游戏专属状态不跨游戏复用。
- 背景只用 `coverFile`，无封面时用主题渐变；**不使用图标当背景**。
- 计时：有运行会话时每秒按 `Date.now() - startedAt` 刷新；无会话归零。
- `processLike = isProcessTarget(exePath)` 决定按钮文案（开始游戏 / 用默认程序打开）、统计栏是否显示时长、是否显示工作目录。
- 操作栏：启动、收藏、编辑、联网补全、自动补全；提示文案通过 `data-tooltip` 提供。
- 自动补全：通过 `openEdit(game, true)` 打开 `GameForm`，由表单获取候选；交互见 [界面与交互.md](界面与交互.md) §4.2。
- 存档备份：`game.savePaths.length === 0` 显示引导；否则显示备份按钮与最近 5 条；还原需两次点击。
- 详情展开：桌面 hover 展开、键盘聚焦展开、点击按钮固定展开；`data-expanded` 控制。
- 封面超分：详情使用独立 `coverSuperres` store 管理档位、两档缓存、任务及订阅生命周期。挂载和封面变化时查询两档缓存；订阅就绪再允许生成，按游戏、档位及唯一任务标识分发事件；订阅后查询当前任务快照，返回详情页也能恢复缩图/保存阶段并取消。进度事件优先于迟到快照，任务结束后的旧进度和旧取消/命令响应不得影响下一任务。完成后重查当前封面缓存以丢弃旧结果。删除期间丢弃旧任务信号；取消返回任务已结束时刷新缓存，避免错过完成事件。初始查询不得覆盖生成/删除结果，卸载后丢弃迟到响应。`coverSuperresSource` 在缓存查询完成后统一选择目标资源，详情只将该资源交给 `coverArtwork` 解码，不并行读取原封面；恢复与回退规则见[界面与交互.md](界面与交互.md) §5。`coverSuperresPreference` 负责偏好读写，存储约定见[数据模型.md](数据模型.md) §2.7；任务快照只恢复任务，不覆盖用户显示选择。

### 3.2 `GameForm` 细节

- 新记录在打开时生成 `id`，因此选封面时可立即按 `id` 命名；取消保存可能留下孤立封面文件（见 §7）。
- 目标选择：文件 → 自动补标题（文件名去扩展名）与工作目录；文件夹 → 标题取目录名，工作目录不自动填。
- 校验：名称、目标路径必填；错误显示在字段下并把焦点移到第一个错误。
- 标签与额外进程名：按中英文逗号拆分、去空白。
- 存档目录：逐个选择、可编辑、可移除；保存时 trim 并丢弃空项。
- 封面与图标：选择后立即复制到数据目录并预览；文件名写入草稿，保存时随记录提交，移除时置空。图像选择/导入期间禁止重复操作、保存与关闭，错误保留草稿并显示提示；图标使用独立资源 URL，规则见 [数据模型.md](数据模型.md) §3。
- 每次挂载创建独立 `gameForm` store，保存原值快照与草稿；自动补全入口连接后获取全部候选，普通编辑只在用户请求时获取单字段。请求只合并实际获取的字段，不接纳返回记录中的其他数据；关闭使请求失效，重入隔离迟到响应。获取错误与无结果不改变草稿。

### 3.3 弹窗与浮层

- `Modal` 使用原生 `dialog.showModal()`，获得焦点陷阱与背景 inert；内部再显式处理 Tab 循环。
- 弹窗面板采用独立表面；设置遮罩只压暗，避免全窗口背景采样，其他弹窗的背景模糊仅由遮罩承担。设置页滚动隔离绘制，避免重叠模糊与整页缩放动画增加合成成本。
- 关闭条件：Escape；同一次主指针在遮罩按下并在面板外抬起；取消/关闭按钮。内部拖选到外部、外部拖到内部均不关闭。
- 卸载时恢复打开前的焦点。
- `Toast` 在弹窗打开时 portal 到 `dialog[open]`，否则到 `#root`，避免被 dialog 顶层遮住。
- `ActionTooltips` 用 portal 渲染到 `#root`，定位避开视口边缘；`aria-describedby` 动态挂到触发按钮。

## 4. 启动、主题与资源

### 4.1 启动

1. `main.tsx`：Tauri 环境设置 `document.documentElement.dataset.starting = "true"`。
2. `App` 挂载后 `init()`。
3. `ready` 后 `showWindowWhenReady()`：`waitForAssets()` → `document.fonts.ready` → 两帧（隐藏 WebView 中每帧 100ms 兜底）→ `show()` → 删除 starting → `setFocus()`。
4. 组件卸载时取消后续显示。

### 4.2 资源

- `GameDetail` 外层跨游戏保留封面节点和 `coverArtwork` store，内容区仍按游戏 id 重建以隔离计时、备份和确认状态。`coverArtwork` 区分缓存待定、明确无图和目标资源；以请求版本丢弃迟到解码，只提交最新目标的 URL 与取景快照。封面节点标记是否属于当前游戏与封面，调整把手不使用过渡旧图的尺寸计算新图取景；过渡显示规则见[界面与交互.md](界面与交互.md) §5。
- `loadAssetUrl(kind, file)`：`asset_path` → `convertFileSrc` → `new Image().decode()`。
- 整个流程 3 秒超时；失败/超时返回 `null`，不阻塞窗口。
- `pendingAssets` 记录未完成请求；`waitForAssets()` 循环等待全部结束。
- `useAssetUrl` 用 `{kind, file, url}` 三元组防止切换游戏时旧图覆盖新图；`kind` 支持 `cover` / `background` / `icon` / `superres`。
- `lib/brand.ts` 集中引用 Tauri 生成的应用图标；`Brand` 复用图标与主题文字呈现品牌组合。内置资源由 Vite 打包，不通过数据目录 IPC 读取。
- `GameIcon` 复用 `useAssetUrl` 解析项目图标，按 [界面与交互.md](界面与交互.md) §2.3 选择显示资源，统一用于侧栏、详情与表单，并在图片显示阶段失败时回退。默认图标只参与显示，不写入 `iconFile`，因此后续选择图标或自动补全仍可正常替换。
- 设置的侧栏背景预览只在左侧栏页请求，并使用异步解码和延迟显示；不在打开常规页时加载无关图片。

### 4.2.1 侧栏背景适配

`backgroundFit.ts` 定义来源、默认参数、像素预算和每消费者最多一个执行中、一个最新待执行的请求队列；重复的执行中请求共用 Promise。`useSidebarBackgroundFit` 观察侧栏实际可视尺寸与 DPR，稳定 200ms 后请求后台；取消、换图及卸载会清除未执行请求，旧结果不得提交。只要存在图片来源就执行适配，不再以历史 `enabled` 字段限制请求。实际侧栏尺寸变化期间复用同来源的已生成图；失败可主动重试当前参数。

`SidebarBackgroundSettings` 按左侧栏页的分组可见性挂载，分组隐藏时卸载并丢弃草稿；归一化历史开关后使用独立草稿及清晰取景预览，还原、切页和关闭丢弃草稿；确认动作在后端保存成功后才更新实际适配。设置写入串行执行，执行时读取最新镜像，防止其他外观修改与确认适配互相覆盖；普通设置保留即时效果。图片预览与右侧控件共用来源，生成期间用原图按草稿方式展示，避免使用旧适配图；技术尺寸折叠展示，无图时禁止提交。

### 4.2.2 封面取景

`App` 按当前游戏和封面文件创建 `coverQuickEdit` 独立状态，传给 `CoverFramingControl` 与 `GameDetail`；实时草稿仅供主区预览，确认后复用 `saveCoverFraming`，不提前修改游戏库。快捷保存串行执行，只保留最新待保存参数；旧响应不清除新草稿，换图后不应用旧记录。`CoverFramingControl` 负责滚轮防抖与 Pointer Lock 生命周期，取消或卸载释放锁定；锁定手势的单击由 `mouseup` 直接完成跳转，屏蔽随后可能到达的鼠标 `click`，避免依赖解锁后的事件投递；键盘及无锁定手势仍由 `click` 激活。交互时序见 [界面与交互.md](界面与交互.md) §2.1。

`CoverFramingSettings` 在设置的封面页按游戏及封面文件隔离草稿，使用主区当前比例预览；`coverFraming.ts` 统一实际封面与预览样式、拖动坐标和缺省值。拖动和滑杆只改草稿，确认后通过 `saveCoverFraming` 更新库，取消、换游戏或关页丢弃修改；失败保留草稿。`GameDetail` 原图与增强图共用取景，侧栏继续使用独立背景适配。联网结果保留原应用入口，新增应用后打开封面页的快捷入口。

### 4.3 主题

- `applyTheme(theme)` 写入 `data-mode`、`data-preset`、`--primary`、`--accent`、`--primary-rgb`、`--accent-rgb`、`--bg-dim`、`--sidebar-overlay-opacity`。
- `sidebarClearGlass` 与原磨砂共同决定封面来源，但开启时优先禁用实际磨砂；`Sidebar` 以 `data-clear-glass` 移除图片滤镜、后方背景模糊、底色和渐变。侧栏与草稿预览按实际磨砂状态请求适配扩边，清晰模式无需扩边。`SettingsPanel` 切换背景效果时同时写入 `sidebarGlass` 与 `sidebarClearGlass`，保持互斥且不覆盖原透明度；旧配置两者均开启时，按实际优先级只选中清晰背景；设置页在全透明背景开启时不挂载透明度调整区域，关闭后按原保存值恢复。
- `presetToTheme` 只替换 `preset/primary/accent`，保留模式、背景、遮罩。
- `system` 模式监听 `prefers-color-scheme` 变化重新应用。
- 背景图 URL 在 `App` 的 layout effect 写入 `--bg-image`，避免首帧闪烁。
- `Sidebar` 用 `useAssetUrl` 单独读取左侧栏背景；磨砂开启且未设独立图片时读取选中游戏原始封面，通过局部 CSS 变量绘制图片层与底色遮罩。`App` 根据自动隐藏设置为常驻侧栏留出主区宽度；`applyTheme` 同步透明度变量。设置面板复用背景导入命令并指定用途，异步选图后从 store 读取最新设置，避免覆盖期间的其他外观修改。
- `Sidebar` 与 `GameDetail` 通过 memo 隔离父级弹窗开关引起的重渲染，侧栏导航回调保持稳定。侧栏列表再与外观分层，列表项按游戏记录、选中与运行状态更新；运行游戏 ID 集合一次派生，避免逐项重复搜索会话。已有独立图片覆盖底色时不再对侧栏背后的画面额外采样，磨砂仍由独立图片层绘制。

### 4.4 窗口

关闭流程由后端 `lifecycle.rs` 管理，交互见 [界面与交互.md](界面与交互.md) §6.1。`App` 订阅 `settings-changed` 同步首次选择；常规设置通过 store 的 `setCloseBehavior` 调用专用 IPC，成功后才更新状态，失败保留旧选择并提示。`CloseDialog` 在加载期与正常界面均挂载，订阅关闭事件后读取快照，用请求版本隔离迟到响应；复用 `Modal` 展示选择、退出警告与错误，提交期间禁用操作与取消。

- `WindowChrome` 只在 Tauri 环境拿到窗口对象；浏览器预览中原生窗口按钮禁用，封面快捷入口仍可用。
- 拖动区不占布局空间；双击最大化由 Tauri 处理。
- 监听 resize，把最大化/全屏状态写入 `data-window-expanded`，CSS 据此把圆角置 0。

## 7. 已知边界（前端）

1. `MetaDialog` 的「手动选择封面」只调用 `importCover` 更新文件与当前内存记录，没有调用 `save_game`；刷新/重启后记录可能仍指向旧封面。需要持久化时应补保存。
2. `GameForm` 选择或自动获取图片会立即生成独立文件；取消表单不会清理未引用资源，可能留下孤儿文件。
3. 资源加载 3 秒超时后返回 `null`，不会自动重试；需要重新挂载（切换游戏/重开应用）才会再次请求。
4. `formatRelative` 在渲染时取当前时间；列表不会随时间自动刷新，直到下一次状态变化。
5. 整库导入后调用 `init()`，但不重置 `nav/query/selectedId`；由视图规则回落到首项。
6. 搜索不覆盖备注、开发商、简介，只匹配标题、分类、标签。

## 8. 扩展指南

### 8.1 新增一个命令

1. 先在 [接口契约.md](接口契约.md) 写签名与错误。
2. Rust 实现并注册（[后端实现.md](后端实现.md)）。
3. `src/types.ts` 加类型；`src/lib/ipc.ts` 加方法。
4. 在 store 或组件中调用，保持「先持久化、后更新内存」。
5. 更新 [版本记录.md](版本记录.md)。

### 8.2 新增一个对话框

1. 在 `useLibrary` 加 `openX/closeX` 与开关字段（若属于全局）。
2. 用 `Modal` 包裹，遵循 [界面与交互.md](界面与交互.md) 的间距与焦点规则。
3. 若涉及异步，创建独立 store 工厂并用生命周期/请求版本丢弃迟到响应。
4. 在 `App` 中按开关挂载；注意 `key` 与卸载清理。

### 8.3 新增一个字段

1. [数据模型.md](数据模型.md) 写字段、默认值、写入者。
2. Rust `models.rs` 加 `#[serde(default)]`；`src/types.ts` 与 `newGameDraft()` 同步。
3. 表单、详情、导入导出按需接入；不必改无关组件。
4. 补迁移说明与测试。

### 8.4 新增视图规则

先改 `lib/library.ts` 的纯函数与测试，再让 `useLibraryView` 消费；不要在组件里复制过滤/排序逻辑。
