## 1. 项目概述

### 1.1 一句话定位

一个**本地游戏库管理器**：把散落在硬盘各处的游戏收进一个漂亮的启动台，点一下就启动，自动记录游玩时长。

### 1.2 要解决的问题

- 游戏装在不同盘、不同文件夹，想玩的时候翻目录翻半天。
- 不知道自己哪个游戏玩了多久、上次玩是什么时候。
- 游戏启动器（Steam / Epic / 独立 exe）各自为政，没有统一入口。

### 1.3 目标（v1.0 必须达成）

1. 添加任意本地游戏（exe），能被记住、被搜索、被分类。
2. 一键启动，启动失败给出明确原因。
3. 启动后自动统计游玩时长，退出后自动结算，重启软件不丢。
4. 数据只存本机，原子写入 + 备份，重装不丢。
5. 外观可自定义：预设主题、主色、背景图。

### 1.4 非目标（v1.0 明确不做）

- 不做游戏下载、安装、更新、DRM。
- 不做云端账号、多人共享、社交功能。
- 不读游戏内存、不做作弊 / Mod 管理。
- 不联网抓取封面（只支持本地图片）。

## 3. 功能范围

### 3.1 v1.0 MVP

**游戏库**
- 添加游戏：选择 exe → 自动填标题（文件名去扩展名）与工作目录。
- 编辑：标题、分类、标签、封面、备注、启动参数、工作目录、额外进程名。
- 删除：只移除库记录，不删本地文件，二次确认。
- 收藏（置顶）、隐藏（从默认列表隐藏，可切换查看）。
- 搜索（标题 / 标签 / 分类模糊匹配）。
- 排序：最近游玩 / 名称 / 累计时长 / 添加时间。
- 分类筛选：内置分类 + 自定义分类。

**启动与计时**
- 点击卡片 → 启动 exe，工作目录正确传递。
- 启动失败（文件不存在、权限不足、CreateProcess 失败）→ 明确错误提示。
- 进程监控：每 2 秒采样；进程全部退出 → 结算本次时长并写库。
- 支持「额外进程名」（应对启动器拉起子进程）。
- 异常退出兜底：启动时写 `pending_session.json`，下次启动按时间差补算。
- 手动修正时长（修正 / 清零）。

**封面**
- 选择本地图片（png / jpg / webp），复制到 `covers/` 按游戏 id 命名。
- 无封面 → 渐变底 + 标题首字母占位。

**外观（重点需求）**
- 预设主题 4 套：鲸鱼娘（默认）、深海、樱花、极简。
- 自定义主色与强调色（颜色选择器）。
- 自定义背景图（本地图片，复制进数据目录），带明暗遮罩强度调节。
- 深色 / 浅色 / 跟随系统三档。
- 所有外观设置即时生效并持久化。

**设置**
- 打开数据目录。
- 导入 / 导出游戏库。
- 版本号与 GitHub 链接。

### 3.2 v1.1（记录在案，v1.0 不做）

- 文件夹扫描自动发现 exe（含 Steam / Epic 库解析）。
- exe 内置图标自动提取。
- 存档备份 / 还原（zip）。
- 时长统计图表（周 / 月）。
- 多语言、开机自启、系统托盘。

## 4. 数据模型与存储

### 4.1 实体

```ts
type Game = {
  id: string;                 // uuid v4
  title: string;
  exePath: string;            // 绝对路径
  workDir: string;            // 默认 exe 所在目录
  args: string;               // 启动参数，原样传递
  extraProcessNames: string[];// 额外进程名（可选）
  coverFile: string | null;   // covers/ 下的文件名
  category: string;           // 内置或自定义
  tags: string[];
  note: string;
  favorite: boolean;
  hidden: boolean;
  playtimeSec: number;
  lastPlayedAt: number | null;// Unix ms
  addedAt: number;
}

type Theme = {
  preset: 'whale' | 'abyss' | 'sakura' | 'mono';
  mode: 'dark' | 'light' | 'system';
  primary: string;            // hex，主色
  accent: string;             // hex，强调色
  backgroundFile: string | null; // backgrounds/ 下文件名
  backgroundDim: number;      // 0–1，遮罩强度
}

type Settings = {
  theme: Theme;
  sort: 'recent' | 'title' | 'playtime' | 'added';
  categories: string[];       // 自定义分类
}

type Session = {  // 运行时状态
  gameId: string;
  pid: number;
  startedAt: number;
  baselinePlaytime: number;
}
```

### 4.2 存储位置

```
%APPDATA%\com.whaledeck.app\
├─ data\games.json
├─ data\settings.json
├─ data\pending_session.json
├─ data\backup\games.<时间戳>.json   # 保留最近 5 份
├─ covers\
└─ backgrounds\
```

### 4.3 写入策略

1. 写入 `*.tmp` → flush → `rename` 覆盖正式文件（NTFS 原子替换）。
2. 覆盖前把旧文件复制到 `backup/`，只保留最近 5 份。
3. 读取失败 / JSON 损坏 → 回退最近备份并提示。
4. 文件带 `schemaVersion`，预留迁移。

## 5. 技术架构

### 5.1 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面壳 | Tauri 2 | 体积小，Rust 侧直接做进程启动与监控 |
| 前端 | React 19 + TypeScript + Vite | 生态成熟、类型安全 |
| 状态 | Zustand | 轻量够用 |
| 样式 | Tailwind CSS v4 + CSS 变量 | 快速出界面，主题可运行时切换 |
| 图标 | lucide-react | 线性图标统一 |
| 文件选择 | tauri-plugin-dialog | 官方插件 |
| 持久化 | 自研 JSON store（serde） | 数据量小、可读可备份 |
| 进程监控 | sysinfo | 跨版本稳定 |

### 5.2 进程模型

- 前端只做展示与交互，文件读写与进程操作全部走 Rust command。
- 启动游戏：`std::process::Command` + `CREATE_NEW_PROCESS_GROUP`，不阻塞 UI。
- 计时线程：每 2s 采样 `sysinfo`：
  - 命中：pid 存活，或存在同 exe 路径进程，或存在额外进程名。
  - 连续 3 次未命中 → 判定退出 → 结算 → 写库 → `game-stopped` 事件。
- 进程启动后立即写 `pending_session.json`；正常结算或软件启动时清理。

| `launch_game` | `id` | `{ pid, startedAt }` | 启动并入监控 |
| `get_sessions` | - | `Session[]` | 运行中游戏 |
| `pick_exe` | - | `string \| null` | 选择 exe |
| `pick_image` | `kind` | `string \| null` | 选择封面 / 背景图 |
| `import_cover` | `{ id, src }` | `string` | 复制封面 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|

## 10. v0.2 功能变更（2026-10-22）

### 10.1 支持任意文件 / 程序 / 文件夹

- 不再限定 `.exe`：快捷方式（`.lnk`）、批处理（`.bat` / `.cmd`）、文档、图片、文件夹都可以加入库。
- 启动方式按目标类型自动选择：
  - `.exe / .bat / .cmd / .com`：以进程方式启动，参与自动计时与进程监控。
  - 其他文件或文件夹：用 Windows Shell 打开（默认程序 / 资源管理器），只记录「最近打开」，不做时长统计。
- 选择文件的对话框不再过滤扩展名，并提供「加入文件夹」入口。
- 绝对路径以 `Path::is_file()` / `is_dir()` 判断，兼容中文与空格。

### 10.2 文件夹扫描

- 新增 `scan_folder`：递归扫描指定目录（默认深度 4、上限 300 个 exe），返回候选列表（路径、名称、大小）。
- 前端「扫描文件夹」对话框：勾选候选后批量加入，自动跳入库中已存在的 exe 路径。

### 10.3 存档备份

- `Game` 新增 `savePaths: string[]`：一个游戏可以有多个存档目录。
- `backup_saves`：把存档目录打包为 zip，存到 `backups/<gameId>/<时间戳>.zip`。
- `list_save_backups` / `restore_save_backup` / `open_backups_dir`。
- 还原前必须二次确认；备份文件不会被自动删除。

### 10.4 数据模型变更

- `Game.savePaths: string[]`（默认空，`#[serde(default)]` 兼容旧数据）。

### 10.5 新增 IPC

| 命令 | 说明 |
|---|---|
| `pick_entry` | 选择任意文件 |
| `scan_folder` | 扫描目录中的 exe，返回候选 |
| `backup_saves` | 打包存档为 zip |
| `list_save_backups` | 列出某游戏的备份 |
| `restore_save_backup` | 还原指定备份 |
| `open_backups_dir` | 打开备份目录 |

### 10.6 验证结果（v0.2）

- `pnpm build` 通过；`pnpm test` 25 项通过；`cargo test` 16 项通过（新增存档备份/还原往返、路径穿越拒绝、备份列表、启动类型判断）。
- `pnpm tauri build` 产出 `WhaleDeck_0.2.0_x64-setup.exe`。
- 扫描限制：最多 6 层目录、500 个结果，跳过 `Windows` / `AppData` / `node_modules` 等系统或依赖目录。
- 还原策略：按备份内 `manifest.json` 记录的原始目录写回，覆盖同名文件，不删除多余文件；必须先二次确认。

### 10.7 安装排障记录（2026-10-22）

**现象**：运行 `WhaleDeck_0.2.0_x64-setup.exe` 提示「无法打开写入文件」。

**根因**：注册表 `HKCU\...\Uninstall\WhaleDeck` 中残留了上一次的 `InstallLocation = D:\xin\WhaleDeck`，而 `D:\xin` 的 ACL 对普通用户只有「读取和执行」权限（`Authenticated Users` 无写权限）。NSIS 沿用旧路径写文件 → 拒绝访问。

**处理**：

1. 删除残留安装记录（`HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\WhaleDeck`）。
2. 安装到可写目录，默认 `%LOCALAPPDATA%\WhaleDeck` 即可。
3. 验证：`WhaleDeck.exe` 正常启动，桌面与开始菜单快捷方式已创建。

**改进**：README 增加排障说明；额外产出便携版 `release/WhaleDeck-0.2.0-portable.zip`；`release/` 加入 `.gitignore`。

### 11.4 合规

- Bangumi / VNDB / 月幕 均要求非商业使用；月幕要求在项目中署名（README 已加「数据来源」章节）。
- 不做批量抓取、不做定时同步，只在用户点击时单次请求。
- 月幕公共 client 有速率限制，请求失败会原样提示，不做自动重试。

## 12. v0.4 自动封面（2026-10-22）

### 12.1 目标

不联网也要有封面：优先从本地游戏目录读取封面图，读不到再提取系统图标。

### 12.2 方案（三层兜底）

1. **本地封面扫描**（`find_local_cover`）
   - 搜索范围：目标同目录、常见图片子目录（`images` / `img` / `art` / `artwork` / `cover` / `covers`）、以及上一级目录（应对 `bin/x64/game.exe` 结构）。
   - 文件名优先级：`cover` / `header` / `capsule` / `poster` / `banner` / `artwork` / `boxart` / `封面` 高于 `logo`、`icon`；`screenshot` / `thumb` 降权。
   - 过滤：只认 `png / jpg / jpeg / webp / bmp`，小于 20 KB 的记为低分。
2. **系统图标提取**（`shell_icon_png`）
   - `SHGetFileInfoW(SHGFI_ICON | SHGFI_LARGEICON)` 取图标 → `GetIconInfo` + `GetDIBits` 转 RGBA → `png` 编码。
   - 对 exe、快捷方式、文件夹、文档都适用（之前「任意文件都能加入」的设定自然延续）。
3. **联网补全**（v0.3 已有）：前两层都没有时才建议用户使用。

### 12.3 接口

- `auto_cover(gameId) -> { coverFile, kind: "local" | "icon", detail }`
- 详情页新增「自动封面」按钮；手动选图与联网补全流程不变。

### 12.4 已知限制

- 系统图标约 32–48px，放大到卡片会偏糊，仅作兜底占位。
- 不解析 exe 内的 256px 图标资源，也不读取 Steam `librarycache` 封面 —— 留给后续版本。

### 12.5 验证（v0.4）

- `cargo test` 27 项通过（新增 5 项：封面命名优先级、子目录查找、小图/非图片忽略、系统图标提取、缺失路径报错）。
- `pnpm build` 通过；`pnpm tauri build` 产出 `WhaleDeck_0.4.0_x64-setup.exe`。
- 实机：详情页「自动封面」按钮可用，本地图片优先，找不到时回退系统图标。

## 13. v0.5 详情页视觉改版（2026-10-22）

### 13.1 参考

Steam 游戏库详情页：顶部宽幅封面占大比例，标题叠在封面上，下方是半透明操作条与信息栏。

### 13.2 变更

- **详情抽屉**：宽度 420 → **480px**；封面从 16:9 小图改为 **300px 高宽幅横幅**（`object-cover`），标题字号放大并叠加在封面底部渐变上。
- **透明玻璃效果**：抽屉整体改为 72% 不透明 + `backdrop-filter: blur(28px) saturate(1.15)`；操作条单独一条毛玻璃横条；信息卡片改用半透明底色。深色/浅色主题都保持可读。
- **操作条上移**：启动/收藏/编辑/联网补全/自动封面从滚动区移到封面正下方的固定横条（与 Steam 一致）。
- **自动封面不再回退 exe 图标**：只做本地图片扫描；找不到时提示使用「联网补全」或手动选择，不把图标当封面。
  - 系统图标提取代码（`cover::icon_png`）保留并标注为可选能力，不参与自动流程。

### 13.3 验收

- 无封面时显示渐变 + 首字母占位，不出现 exe 图标。
- 有封面时横幅高度 300px，标题与分类可读。
- 抽屉与操作条的透明/模糊在深色与浅色主题下都不影响文字对比度。
