## 1. 总体形态

```text
┌─────────────────────────────────────────────────────────────┐
│ Tauri WebView（React 19 + TypeScript + Vite）                │
│  UI / 交互 / 视图状态 / 主题 / 资源 URL                      │
│  不直接读写文件、不直接发网络请求                             │
└──────────────────────────┬──────────────────────────────────┘
                           │ Tauri IPC（invoke / event）
┌──────────────────────────▼──────────────────────────────────┐
│ Rust 核心（Tauri 2）                                         │
│  命令层 commands.rs                                          │
│  领域层 launcher / store / cover / meta / savegame / program │
│  Windows API（进程、Shell、版本资源、图标、GDI、ShellExecute）│
└──────────────────────────┬──────────────────────────────────┘
                           │
        %APPDATA%\com.whaledeck.app\（JSON / 图片 / zip）
```

**边界规则**

- 前端只做展示与交互；文件、进程、网络、Windows API 全部在 Rust。
- Rust 是持久化数据的唯一写入者；前端只持有内存镜像。
- 前端通过 `src/lib/ipc.ts` 的 `api` 对象访问命令，不在组件里拼命令名。
- 外部副作用（写盘、启动、下载）失败必须以中文错误返回，由前端统一提示。

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面壳 | Tauri 2 | 体积小；Rust 直接做进程与 Windows 集成 |
| 前端 | React 19 + TypeScript（strict） | 组件化；类型与 Rust 模型一一对应 |
| 构建 | Vite 7 + `@vitejs/plugin-react` 5 | 固定端口 1420；不监听 `src-tauri/` |
| 状态 | Zustand 5 | 全局库状态 + 每个对话框独立的 vanilla store |
| 样式 | Tailwind CSS v4 + `src/styles.css` + CSS 变量 | 布局用工具类，组件规则与主题令牌集中管理 |
| 图标 | lucide-react | 线性图标 |
| 文件选择 | tauri-plugin-dialog | 系统原生对话框 |
| 持久化 | 自研 JSON Store（serde） | 数据量小、可读、可手工备份 |
| 进程监控 | sysinfo 0.33 | 每会话一个采样线程 |
| 网络 | reqwest（rustls） | 仅元数据搜索与封面下载 |
| 图像 | png + Windows GDI/Shell API | 图标提取；封面为文件复制 |

依赖版本以 `package.json` / `src-tauri/Cargo.toml` 为准；版本号同步规则见 [工程规范.md](工程规范.md)。

## 3. 进程与线程模型

### 3.1 主进程

- Tauri 主线程：窗口、事件循环、命令调度。
- `setup` 阶段完成：解析数据目录、建目录、载入游戏库与设置、恢复异常会话，然后注册 `AppState`。
- 窗口初始 `visible: false`；前端准备就绪后由 JS 调 `show()` + `setFocus()`（见 §5.1）。

### 3.2 共享状态

`AppState` 持有 `store`、`games: Mutex<Vec<Game>>`、`settings: Mutex<Settings>`、`sessions: Mutex<Vec<Session>>` 与 `lifecycle: Mutex<Lifecycle>`；关闭状态与跨操作互斥由生命周期状态统一管理，见 [后端实现.md](后端实现.md) §1。

- 所有共享状态都是进程内内存；磁盘写入通过 `Store`。
- **写盘成功后才替换内存**（save / update 路径），避免写失败污染内存。
- 会话列表是「正在计时的进程」索引；前端通过 `get_sessions` 与 `game-stopped` 事件保持同步。

### 3.3 计时线程

- 每个以进程方式启动的游戏创建一个 `std::thread`。
- 每 2 秒采样一次；连续 3 次未命中判定退出；线程在结算、写库、发事件后结束。
- 线程通过 `app.state::<AppState>()` 访问共享状态；发现会话已被移除时自行退出。
- 线程不持有前端引用；结果只通过 `game-stopped` 事件广播。

### 3.4 异步命令

`search_meta` / `apply_meta` 是 `async` 命令，运行在 Tauri 异步运行时；其余命令为同步命令。联网请求不阻塞 UI 线程。

## 5. 关键流程

### 5.1 启动与首帧

1. `tauri.conf.json` 中主窗口 `visible: false`。
2. Rust `setup`：初始化数据目录、载入库与设置、恢复 pending 会话、注册状态。
3. WebView 加载；`main.tsx` 在 Tauri 环境设置 `documentElement.dataset.starting = "true"`。
4. `App` 调 `init()`：并行读取游戏、设置、运行会话。
5. 主题与背景图在 layout effect 中应用；图片通过 `loadAssetUrl` 并行解码（3 秒超时兜底）。
6. `ready` 后调用 `showWindowWhenReady()`：等待资源、`document.fonts.ready`、两帧，然后 `show()` → 清除 starting → `setFocus()`。
7. 加载失败也会把 `ready` 置真，保证窗口能显示错误提示，而不是永久隐藏。

### 5.2 启动游戏与结算

```text
前端 launchGame(id)
  → IPC launch_game
    → 校验记录存在、未在运行
    → spawn_entry：进程目标 spawn，其余 ShellExecute
    → 进程目标：创建 Session、写 pending、启动监控线程
    → 更新 lastPlayedAt 并落盘
  → 前端乐观更新 lastPlayedAt 与 sessions（pid 非空时）
  → 监控：2s 采样，连续 3 次未命中
    → 累加时长、写库、移除会话、清 pending、emit game-stopped
  → 前端 handleStopped：移除会话、更新累计时长、Toast
```

细节与错误分支见 [后端实现.md](后端实现.md) 启动与监控、[前端实现.md](前端实现.md) 写入与运行状态。

### 5.3 联网补全

1. 详情页打开 `MetaDialog`，用当前标题初始化独立检索 store。
2. 提交时生成请求版本号；只有最新版本能改结果/加载态/发通知。
3. `search_meta` 在 Rust 侧请求所选数据源并归一化为 `MetaItem[]`。
4. 用户点「应用」→ `apply_meta`：下载封面（白名单 + 12MB）到 `covers/`，更新非空字段与来源，落盘返回完整 `Game`。
5. 前端用返回值替换当前记录，不重载全库。

### 5.4 自动补全

详情操作打开复用的项目表单 → `autofill` 接收当前草稿生成本地候选 → 前端在表单 store 中合并候选 → 用户确认后 `save_game` 持久化并更新游戏库。

普通编辑的逐字段获取复用同一候选链路；后端不持有表单状态。获取实现见 [后端实现.md](后端实现.md) §8.4，接口见 [接口契约.md](接口契约.md) §2.9。

### 5.5 存档备份与还原

- 详情页为每个游戏创建独立 `saveBackups` store；组件卸载即失效，迟到响应不再写 UI。
- 备份：Rust 将每个存档目录递归写入 zip，条目前缀为目录序号；`manifest.json` 记录原始目录。
- 还原：校验文件名与相对路径，按 manifest 写回原目录；覆盖同名文件，不删除多余文件；必须二次确认。
- 同一详情内备份与还原共享忙碌状态，防止交叉写入。

### 5.6 导出与导入

- 导出：保存 JSON（游戏 + 设置 + schemaVersion），并把 `covers/` 复制到同级的 `<文件名>.covers/`。
- 导入：读取 JSON，整体替换内存与磁盘，再复制封面；返回导入数量。
- 导入是覆盖操作，前端需二次确认。格式细节见 [数据模型.md](数据模型.md)。

## 6. 信任边界与安全

| 边界 | 措施 |
|---|---|
| 资源访问 | Tauri asset protocol 只开放 `$APPDATA/**`；前端只拿路径，不读任意盘 |
| 外部图片 | 只允许 `https://lain.bgm.tv/`、`https://t.vndb.org/`、`https://cdn.ymgal.games/`；限制 12MB |
| 路径 | 全程 `Path`/`PathBuf`；启动参数先拆分再逐个传，不拼 shell 字符串；中文/空格路径可用 |
| 存档还原 | 拒绝 `..`、盘符、绝对路径与含分隔符的备份名；只写 manifest 记录的目录 |
| 窗口 | 无边框透明；自绘控制键；浏览区不可选中（输入框除外） |
| 网络 | 只在用户操作时发请求；不做后台轮询；月幕 token 仅存内存 |
| CSP | 当前为 `null`（Tauri 默认）；新增远程内容前必须重新评估 |

## 7. 一致性与失败策略

| 场景 | 策略 |
|---|---|
| 写游戏/设置失败 | Rust 内存保持旧值（save/update 先写盘）；前端设置是乐观更新，失败只提示，不回滚到旧值 |
| 主 JSON 损坏 | 隔离为 `games.corrupt.<ms>`，回退最近备份；无备份则空库 |
| 程序异常退出 | 下次启动按 pending 时间差补算，上限 12 小时 |
| 启动失败 | 返回中文原因并广播 `launch-failed`；不创建会话 |
| 迟到 IPC 响应 | 对话框 store 用版本号/生命周期丢弃旧响应 |
| 图片缺失/卡住 | 3 秒超时返回 `null`，不阻塞窗口显示 |
| 备份刷新失败 | 保留已确认的备份记录与成功提示，不把刷新失败当备份失败 |

已知边界与限制集中列在 [后端实现.md](后端实现.md) 末尾和 [数据模型.md](数据模型.md) 末尾，避免散落。
