# 数据模型与存储

> 本文是实体字段、存储布局、写入/恢复策略与迁移规则的**唯一权威**。
> 命令签名见 [接口契约.md](接口契约.md)，字段如何参与界面见 [前端实现.md](前端实现.md)。

---

## 1. 序列化约定

- Rust 结构体统一 `#[serde(rename_all = "camelCase")]`；磁盘 JSON、IPC、TypeScript 类型三处字段名一致。
- 时间单位：**Unix 毫秒**（`u64` / `number`）；时长单位：**秒**（`u64` / `number`）；大小单位：**字节**。
- 可空值统一用 `null` / `Option<T>`，不使用空字符串表示「没有」。
- 新字段一律加 `#[serde(default)]`，保证旧数据可读；删除/改名属于破坏性变更，必须提升 `SCHEMA_VERSION` 并写迁移。
- `schemaVersion` 当前为 **1**，仅写入 `games.json` 与整库导出文件；读取时允许没有该字段。

## 2. 实体

### 2.1 `Game`（游戏 / 项目记录）

| 字段 | 类型 | 默认 | 含义与约束 |
|---|---|---|---|
| `id` | string | 无 | UUID v4；新增时若为空由后端生成；封面/图标/备份都以它为键 |
| `title` | string | `""` | 显示名称；保存时不能为空（后端校验） |
| `exePath` | string | `""` | 目标绝对路径；文件或文件夹；保存时不能为空 |
| `workDir` | string | `""` | 进程启动的工作目录；空表示「程序所在目录」 |
| `args` | string | `""` | 启动参数字符串；启动时按双引号规则拆分 |
| `extraProcessNames` | string[] | `[]` | 额外进程名；任一存在即视为仍在运行 |
| `coverFile` | string \| null | `null` | `covers/` 下的文件名；主区背景与卡片封面 |
| `coverFraming` | CoverFraming \| null | `null` | 主区封面取景；`{ file: string, positionX: number, positionY: number, zoom: number }`，绑定原封面文件，位置 0–100、缩放 1–3。缺省或文件不匹配时居中、1 倍；只影响显示，原图与超分缓存不变 |
| `iconFile` | string \| null | `null` | `icons/` 下的文件名；侧栏缩略图 |
| `category` | string | `""` | 单个分类名；空显示为「未分类」 |
| `tags` | string[] | `[]` | 标签；参与搜索 |
| `note` | string | `""` | 备注；自动补全可能写入 |
| `favorite` | boolean | `false` | 收藏；最近排序中置顶 |
| `hidden` | boolean | `false` | 隐藏；只在「已隐藏」视图出现 |
| `playtimeSec` | number | `0` | 累计游玩秒数；可手动修正 |
| `lastPlayedAt` | number \| null | `null` | 最近一次启动时间（Unix ms） |
| `addedAt` | number | `0` | 加入时间；为 0 时后端写入当前时间 |
| `savePaths` | string[] | `[]` | 存档目录列表；保存时去空白、丢空项 |
| `source` | string | `""` | 元数据来源：`bangumi` / `vndb` / `ymgal`；空表示手动 |
| `sourceId` | string | `""` | 来源条目 ID |
| `developer` | string | `""` | 开发商 / 公司 |
| `releaseDate` | string | `""` | 发售日期；原样字符串（通常 `YYYY-MM-DD`） |
| `summary` | string | `""` | 简介 |

写入者：`save_game`（新增/编辑/收藏/确认补全）、`save_cover_framing`（只改取景）、`reset_playtime`、`launch_game`（只改 `lastPlayedAt`）、监控线程（`playtimeSec` / `lastPlayedAt`）、`apply_meta`、`import_library`。

| `sidebarGlass` | boolean | `false` | 左侧栏磨砂效果；与自动隐藏独立保存 |

| `sidebarTransparency` | number | `0.52` | 左侧栏底色透明度，0–1；0 为不透明，1 为完全透明；只影响底色，不影响文字和控件 |
| `sidebarBackgroundFit` | SidebarBackgroundFit | 见 §2.6 | 侧栏适配方式、取景参数及历史兼容字段 |

### 2.3 `Settings`

| 字段 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `theme` | Theme | 见上 | 外观 |
| `sort` | `"recent" \| "title" \| "playtime" \| "added"` | `"recent"` | 排序偏好；启动时同步到前端 |
| `categories` | string[] | `[]` | 自定义分类；与游戏实际分类合并展示 |
| `closeBehavior` | `"exit" \| "hide" \| null` | `null` | 关闭行为；空值表示尚未确认，旧设置读取时使用空值 |

### 2.4 `Session`（运行时）

| 字段 | 类型 | 含义 |
|---|---|---|
| `gameId` | string | 所属游戏 |
| `pid` | number | 启动得到的进程 ID |
| `startedAt` | number | 启动时间（Unix ms） |
| `baselinePlaytime` | number | 启动前的累计秒数 |

同时用于 `pending_session.json` 的持久化。只在内存中表示「运行中」；进程退出或异常恢复后移除。

### 2.5 其他传输类型

| 类型 | 字段 | 用途 |
|---|---|---|
| `LaunchResult` | `pid: number \| null`、`startedAt` | 启动结果；`pid` 为 `null` 表示用系统默认程序打开，不计时 |
| `StoppedPayload` | `gameId`、`sessionSec`、`playtimeSec` | `game-stopped` 事件载荷；单次时长与结算后的累计 |
| `ScanEntry` | `path`、`name`、`size` | 扫描候选 exe |
| `SaveBackup` | `file`、`createdAt`、`size` | 一次存档备份的元信息 |
| `MetaItem` | `source`、`id`、`title`、`subtitle`、`coverUrl`、`releaseDate`、`developer`、`summary`、`rating` | 联网检索结果 |
| `AutofillResult` | `game`、`icon`、`cover`、`coverDetail`、`filled` | 未持久化的候选草稿；`filled` 是获取到的中文文本字段名 |
| `AutofillField` | `"title" \| "developer" \| "note" \| "iconFile" \| "coverFile"` | 可按字段请求的本地候选 |
| `CloseRequest` | `kind: "choose" \| "confirmExit" \| "error"`、`runningCount: number`、`message: string` | 待确认关闭请求；错误阶段只允许取消 |

TypeScript 对应定义在 `src/types.ts`；Rust 实体在 `src-tauri/src/models.rs`，自动补全传输类型在 `src-tauri/src/commands.rs`，两边必须同步修改。

### 2.6 侧栏背景适配

`Theme.sidebarBackgroundFit` 为独立配置：`{ enabled: boolean, mode: "contain" | "cover" | "stretch", positionX: number, positionY: number }`。默认完整显示、水平和垂直取景均为 50；位置使用 0–100。`enabled` 保留用于兼容历史文件，默认 `true`；前端始终执行适配，忽略旧值 `false`，确认取景时写入 `true`。TypeScript 为兼容旧数据允许该字段缺省，Rust 反序列化补默认值。

适配派生 PNG 位于数据根目录 `background-fit/`，不替换 `backgrounds/` 或 `covers/` 原图，不进入整库导出。缓存以原图内容、目标像素、方式、取景、磨砂扩边及算法版本组成键；仅缓存可重新生成的图片，不创建应用版本备份。

### 2.7 封面增强显示偏好

WebView 的 `localStorage` 按游戏使用 `whaledeck.cover-superres.<gameId>` 键保存 `{ preset: "efficient" | "quality", showEnhanced: boolean }`，不保存派生文件路径，不进入游戏库 JSON 或整库导出。手动切档、切换原图/增强图及生成成功时更新；没有记录或记录损坏时按[界面与交互.md](界面与交互.md) §5 初始化。存储不可用时使用当前进程内的偏好记忆。更换封面保留显示偏好，但重新查询派生缓存，不复用旧文件。

### 2.8 展示页过渡偏好

`Theme.detailBackgroundTransition`：`"none" | "blur" | "crossfade" | "slideRight" | "slideLeft" | "slideDown" | "slideUp"`，默认 `"blur"`。`Theme.detailTextTransition`：`"none" | "fade" | "stagger" | "scramble"`，默认 `"fade"`。两项独立保存到设置，随整库导出/导入保留；旧设置缺省时由 Rust 补默认值，TypeScript 允许缺省并使用相同默认值。未知枚举值退回各自默认值，避免整份设置读取失败。效果与时序见[界面与交互.md](界面与交互.md) §2.2.1。

## 3. 存储布局

数据根目录由 Tauri 的 `app_data_dir()` 解析，标识符 `com.whaledeck.app`，Windows 下通常为：

```text
%APPDATA%\com.whaledeck.app\
├─ data\
│  ├─ games.json                 # { schemaVersion, games: Game[] }
│  ├─ settings.json              # Settings
│  ├─ pending_session.json       # 异常退出时的会话（可能不存在）
│  ├─ games.corrupt.<ms>         # 解析失败时隔离的现场（可能不存在）
│  └─ backup\
│     ├─ games.<ms>.json         # 最近 5 份游戏库备份
│     └─ settings.<ms>.json      # 最近 5 份设置备份
├─ covers\<gameId>.<ext>         # 兼容历史封面
├─ covers\<gameId>.<uuid>.<ext>  # 手选、自动获取的草稿或联网应用封面；独立文件避免旧图缓存及取景复用
├─ icons\<uuid>.png              # 自动提取的草稿图标（历史文件也可能以 gameId 命名）
├─ icons\<gameId>.<uuid>.<ext>     # 手动导入的图标（列表缩略图）
├─ backgrounds\background.<uuid>.<ext>  # 应用背景（兼容旧 background.<ext>）
├─ backgrounds\sidebar-background.<uuid>.<ext>  # 左侧栏独立背景
├─ superres\<gameId>-<hash>-efficient.png  # 效率档，兼容既有缓存
├─ superres\<gameId>-<hash>-quality-anime6b-2x-v1.png  # 质量档（模型、倍率、缩放算法版本）
├─ background-fit\fit-v1-<hash>.png  # 可再生成的侧栏尺寸适配图
└─ backups\<gameId>\<createdAt>.zip  # 每个游戏的存档备份
```

- 目录在启动时创建；资源目录按需再建。
- 联网封面的旧文件仍按同一 `id` 前缀清理。
- 表单的手动图片与自动获取图片每次使用独立文件名，避免覆盖已保存资源并确保预览刷新；取消、恢复或移除只丢弃草稿引用，不清理图片文件。
- 应用背景与左侧栏背景使用不同前缀及独立引用，每次更换用唯一文件名刷新图片缓存；复制与设置落盘成功后才清理对应前缀的旧图，两个用途不相互清理。清除背景只移除设置引用。
- 派生图与 `covers/` 分开：整库导出会复制 `covers/` 的全部文件，派生图不应混入；文件名带原图内容哈希与预设版本，两档可同时保留；原图替换后旧结果不再命中。删除增强图会移除该游戏两档缓存。删除游戏记录当前不清理 `superres/`。
- 删除游戏记录不会删除 `covers/` / `icons/` / `backups/` 下的文件（当前实现）。

## 4. 文件格式

### 4.1 `games.json`

```json
{
  "schemaVersion": 1,
  "games": [
    {
      "id": "…",
      "title": "星露谷物语",
      "exePath": "C:\\Games\\Stardew Valley\\Stardew Valley.exe",
      "workDir": "C:\\Games\\Stardew Valley",
      "args": "",
      "extraProcessNames": [],
      "coverFile": "…jpg",
      "iconFile": "….png",
      "category": "种田",
      "tags": ["像素"],
      "note": "",
      "favorite": true,
      "hidden": false,
      "playtimeSec": 7200,
      "lastPlayedAt": 1760000000000,
      "addedAt": 1759000000000,
      "savePaths": ["C:\\Users\\…\\AppData\\Roaming\\StardewValley\\Saves"],
      "source": "bangumi",
      "sourceId": "12345",
      "developer": "ConcernedApe",
      "releaseDate": "2016-02-26",
      "summary": "…"
    }
  ]
}
```

读取兼容两种形态：

1. 上面的对象（推荐）；
2. **裸数组**（历史格式），等价于没有 `schemaVersion` 的 `games`。

### 4.2 `settings.json`

直接序列化 `Settings`。文件缺失或解析失败 → 使用默认设置（不读备份）。

### 4.3 `pending_session.json`

直接序列化一个 `Session`。只在以进程方式启动成功时写入；正常结算或下次启动恢复后删除。

### 4.4 整库导出文件

```json
{
  "schemaVersion": 1,
  "games": [ /* Game[] */ ],
  "settings": { /* Settings */ }
}
```

导出时在同级目录额外生成 `<导出文件名去扩展名>.covers/`，包含 `covers/` 下的全部文件（不递归）。导入只恢复游戏与设置，并复制该封面目录；图标、背景图、存档 zip 不包含在整库导出中。

### 4.5 存档备份 zip

- 文件名：`<createdAt 毫秒>.zip`，位于 `backups/<gameId>/`。
- 根条目 `manifest.json`：`{ "version": 1, "sources": ["原始目录", …] }`。
- 文件条目：`<sources 下标>/<相对路径>`，例如 `0/Saves/slot1/data.sav`。
- 空目录不写入；没有任何文件时删除 zip 并报错。
- 还原规则与路径安全见 [后端实现.md](后端实现.md) 存档备份。

## 5. 写入策略

### 5.1 原子写入

所有 JSON 写入都经过 `atomic_write`：

1. 写入同目录的 `<文件名>.tmp`；
2. `flush` + `sync_all`；
3. `rename` 覆盖正式文件（Windows 同卷替换）。

任一步失败返回中文错误；正式文件保持原样。

### 5.2 备份与保留

- 正式文件已存在时，写入前先复制到 `data/backup/<stem>.<毫秒>.json`。
- 每种文件（`games` / `settings`）各自保留最近 **5** 份；按文件名中的时间戳排序删除最旧。
- 备份是「写入前快照」，不是每次启动的快照。

### 5.3 损坏处理

- `games.json` 读取失败：若文件存在，重命名为 `games.corrupt.<毫秒>` 保留现场；然后回退到 `backup/` 中**修改时间最新**的 JSON；仍失败则返回空库。
- `settings.json` 读取失败：直接使用默认设置，不隔离、不回退。
- `pending_session.json` 读取失败：视为没有待恢复会话，删除文件。

### 5.4 异常会话恢复

启动时若存在 `pending_session.json`：

1. 计算 `now - startedAt`；
2. 仅当 `0 < 差值 < 12 小时` 且能找到对应 `gameId` 时，把秒数累加到 `playtimeSec` 并立即写库；
3. 无论是否补算，最后都删除 pending 文件。

约束：pending 只有一个文件。同时运行多个进程目标时，后启动的会覆盖前一个；任一线程正常结算都会清除它。这是当前实现的已知边界，见 §8。

用户确认正常退出时，所有在内存中的会话结算至退出时刻，写库成功并清除 pending 后才退出；不会在下次启动时把离线时间补入。写盘或清除 pending 失败时保留会话、阻止退出，供用户重试。

## 6. 一致性规则

| 操作 | 规则 |
|---|---|
| 新增 / 编辑 / 收藏 | 先构造候选列表 → 写盘成功 → 替换内存 → 返回完整记录 |
| 删除 | 运行中的记录禁止删除；从内存移除后写盘（写失败时内存可能已变化，见 §8） |
| 启动 | 启动成功后才写 `lastPlayedAt`；失败不产生会话 |
| 结算 | 在锁内累加 `playtimeSec`、写盘、移除会话、清 pending、发事件 |
| 导入 | 整体替换游戏与设置，分别写盘；不合并 |
| 手动修正时长 | 直接覆盖 `playtimeSec`，写盘成功后返回快照 |

## 7. 路径与比较规则

- 所有路径按 Windows 绝对路径处理；允许中文、空格、正/反斜杠。
- 工作目录为空时，后端取目标父目录；目标本身是文件夹时不使用工作目录。
- 前端批量去重使用 `gamePathKey`：`trim` → `/` 转 `\` → 小写。后端不做路径去重。
- 存档目录保存前 `trim` 并丢弃空字符串；备份/还原时原样使用。
- 文件名比较（封面/图标/备份）区分大小写取决于文件系统；扩展名判断统一转小写。

## 8. 迁移与已知边界

### 8.1 迁移规则

- 新增字段：Rust 加 `#[serde(default)]`，TypeScript 类型与 `newGameDraft()` 同步补默认值。
- 语义变更/删除字段：提升 `SCHEMA_VERSION`，在 `load_games` 中按版本转换后再返回；旧备份仍需可读。
- 不写「一次性迁移脚本」；迁移必须在读取路径内完成，且可重复执行。

### 8.2 已知边界（当前实现）

1. `pending_session.json` 只支持一个会话，多开进程目标时可能互相覆盖；补算时间上限 12 小时。
2. `settings.json` 损坏不隔离、不回退备份。
3. `delete_game` 先改内存再写盘，写盘失败时内存与磁盘可能不一致；UI 会提示错误，但需重新载入恢复。
4. 删除记录不清理封面/图标/存档备份；整库导入不清理旧图标/背景。
5. 整库导出不包含图标、背景图、存档 zip。
6. 备份列表按文件名时间戳排序；同名毫秒内重复备份可能覆盖（概率极低）。
7. 未做磁盘空间预检；超大存档目录会占用较多时间与空间。
