## 1. 模块与装配

| 模块 | 入口 | 职责 | 关键依赖 |
|---|---|---|---|
| `lib.rs` | `init_app` / `run` | 装配状态、恢复 pending、注册命令与托盘、拦截窗口关闭 | Tauri |
| `commands.rs` | `AppState` | 命令实现、启动监控、扫描、资源、导入导出、自动补全 | 所有领域模块 |
| `store.rs` | `Store` | JSON 原子写入、备份、损坏回退、pending | serde_json |
| `launcher.rs` | `spawn_entry` / `is_running` | 进程或 Shell 启动、参数拆分、运行判定 | std::process、sysinfo、ShellExecuteW |
| `cover.rs` | `find_local_cover` / `icon_png` | 本地封面评分、系统图标提取、PNG 编码 | GDI、Shell、png |
| `program.rs` | `read_version_info` | 读取 exe 版本资源 | Win32 版本 API |
| `meta.rs` | `search` / `download_image` | 三家数据源检索、图片白名单与下载 | reqwest |
| `savegame.rs` | `backup` / `list` / `restore` | 存档 zip 打包与安全还原 | zip |
| `models.rs` | 结构体 | 序列化模型、默认值、`now_ms` | serde |
| `lifecycle.rs` | `setup_tray` / `request_close` | 托盘、关闭请求状态与退出结算 | Tauri tray、事件 |
| `superres.rs` | `SuperRes` / `execute` | 封面超分：辅助进程调度、进度事件、取消、派生图缓存 | std::process、Tauri 事件 |
| `file_memo.rs` | `FileMemo::get` | 根据文件属性复用只读计算，限制条目数 | std::fs |

关闭交互见 [界面与交互.md](界面与交互.md) §6.1。装配层创建托盘并拦截主窗口 `CloseRequested`，保留窗口供隐藏或取消；托盘退出也交给 `lifecycle`。后端保留待确认请求并发送事件，由前端复用 `Modal` 展示；前端订阅后读取请求快照，避免启动期间漏掉事件。

生命周期锁串行化关闭请求、进程启动与会话结算；确认期间拒绝新启动，取消后恢复，避免确认后又加入未获确认的运行程序。监控结算必须在锁内再次检查会话存在，防止与退出结算重复累加。正常退出先生成候选游戏库并落盘，再清除 pending 和内存会话；失败时不退出、不替换内存。关闭偏好只更新对应字段并在持有设置锁时写盘，首次选择成功后广播设置快照。

`run()` 依次：注册 dialog 插件 → `setup` 调 `init_app` → 注册命令 → 运行。`init_app` 的顺序是：解析 `app_data_dir` → `Store::new` → `ensure_dirs` → `load_games` → pending 补算 → `load_settings` → `app.manage(AppState)`。

## 2. 共享状态与锁

`save_cover_framing` 在游戏库锁内校验当前封面文件与取景来源一致，只修改候选副本的取景字段；写盘成功后替换内存。拒绝非有限数、越界参数、缺少封面、已删除游戏或已更换封面的迟到保存，避免覆盖并发更新的时长或元数据。

联网应用封面采用独立文件引用并清除该游戏的旧取景；元数据同样在候选副本上落盘成功后才替换内存。没有下载新封面时保留原取景。

```rust
pub struct AppState {
    pub store: Store,
    pub games: Mutex<Vec<Game>>,
    pub settings: Mutex<Settings>,
    pub sessions: Mutex<Vec<Session>>,
}
```

- 三个 `Mutex` 互相独立；**不要**在持锁期间调用可能再次取同一把锁的函数（会死锁）。
- `store` 无内部可变状态，可在持锁期间调用。
- 锁中毒时当前实现使用 `unwrap()`；崩溃后重启即可恢复，不使用 `parking_lot`。
- 写路径统一遵循：构造候选数据 → 写盘 → 成功后才替换内存。
- `find_game` 克隆记录，避免把锁引用带到后续写路径。

## 3. 游戏库命令

### 3.1 `save_game_record`

1. 校验 `title.trim()`、`exe_path.trim()` 非空，否则返回中文错误。
2. `id` 为空 → UUID v4；`added_at == 0` → `now_ms()`。
3. `save_paths` 逐项 trim、丢弃空项。
4. 克隆当前 `games` 为候选列表，按 `id` 替换或追加。
5. `store.save_games(&next)` 成功后才 `*games = next`，返回保存后的记录。
6. 写盘失败 → 返回错误，内存与磁盘都保持旧状态。

### 3.2 `delete_game`

1. 若 `sessions` 中已有该 `game_id` → 报错「正在运行中，请先退出再删除记录」。
2. `games.retain` 后长度不变 → 返回 `false`。
3. `save_games` 写盘；失败返回错误（此时内存已移除，见 §13）。

### 3.3 `reset_playtime`

直接覆盖 `playtime_sec`，写盘成功后返回克隆；写盘失败时内存已被修改（见 §13）。

## 4. 启动与计时

### 4.1 `launch_game`

1. `find_game` 取记录；同一 `game_id` 已在 `sessions` → 报错。
2. `launcher::spawn_entry(&game)`：
   - 失败：广播 `launch-failed`（`{gameId, message}`），同时返回 `Err(message)`。
3. `started_at = now_ms()`。
4. `pid` 非空：
   - 构造 `Session { game_id, pid, started_at, baseline_playtime }`；
   - 加入 `sessions`；
   - 写 `pending_session.json`（失败忽略，不阻断启动）；
   - 启动监控线程。
5. 无论是否进程目标，更新该记录的 `last_played_at = started_at` 并写库（失败忽略，返回值仍成功）。
6. 返回 `LaunchResult { pid, started_at }`。

### 4.2 监控线程

```text
loop:
  sleep 2s
  若会话已不在 sessions（被移除）→ 线程结束
  若 is_running → misses = 0
  否则 misses += 1；连续 3 次 → 结束循环
结算:
  session_sec = (now - started_at) / 1000
  playtime_sec = 该记录当前累计 + session_sec
  更新 last_played_at = started_at
  save_games
  从 sessions 移除该会话
  clear_pending
  emit game-stopped { gameId, sessionSec, playtimeSec }
```

- 判定退出最多延迟约 6 秒（3 次 × 2 秒），这段时间会计入本次时长。
- 结算失败（写盘）仍会移除会话并清 pending，时长只存在于返回值/事件中；这是当前实现的边界。
- `clear_pending` 是全局的，多会话时可能清掉别的游戏的 pending（见 §13）。

### 4.3 `is_running`

每次采样新建 `System` 并刷新全部进程，然后按以下顺序判断：

1. `session.pid` 仍存在 → 运行中；
2. 任一进程的可执行路径（小写）等于 `game.exe_path`（小写）→ 运行中；
3. 任一进程名（小写）等于目标 exe 文件名（小写）→ 运行中；
4. 任一进程名命中 `extra_process_names`（去空白、小写）→ 运行中。

注意：同名进程可能造成误判；PID 也可能被系统复用。当前不做启动时间校验。

### 4.4 `spawn_entry`

1. 目标不存在 → 「路径不存在：…」。
2. 目标是文件夹 → `shell_open`，返回 `None`。
3. 扩展名不在 `exe/bat/cmd/com` → `shell_open`，返回 `None`。
4. 工作目录：`work_dir` 非空用其 trim 值，否则取目标父目录；目录不存在 → 「工作目录不存在：…」。
5. `Command::new(target)` + `current_dir(work_dir)` + 逐个 `arg`；加 `CREATE_NEW_PROCESS_GROUP (0x0000_0200)`。
6. `spawn` 成功返回 `Some(pid)`；失败返回「启动失败（路径）：…。可能是文件损坏、缺少运行库或权限不足。」

`shell_open` 用 `ShellExecuteW` 的 `open` 动作，返回值 ≤ 32 视为失败，提示「系统无法打开：…（可能没有关联程序，或文件已被移动）」。

### 4.5 参数拆分

`split_args` 只识别双引号：引号内空格保留，引号本身不进入参数；连续空格被折叠；空输入返回空列表。不支持反斜杠转义、单引号或环境变量展开。

### 4.6 `is_process_target`

按扩展名判断，大小写不敏感，仅 `exe` / `bat` / `cmd` / `com`。前端 `types.ts` 用同一规则（小写扩展名 + 必须含 `.`）。

## 5. 存储实现

### 5.1 目录

`Store::ensure_dirs` 创建 `data/`、`data/backup/`、`covers/`、`icons/`、`backgrounds/`；`backups/<id>/` 按需创建。路径方法见 [数据模型.md](数据模型.md) §3。

### 5.2 读取

- `load_games`：主文件解析失败且存在 → 重命名为 `games.corrupt.<ms>`；再取 `backup/` 中修改时间最新的 JSON；仍失败返回空 `Vec`。
- `read_games_file`：先解析为 `Value`；数组直接作为 `Game[]`，对象取 `games` 字段；字段级反序列化失败按整体失败处理。
- `load_settings`：读取失败或解析失败 → `Settings::default()`，不回退备份。
- `read_pending`：解析失败 → `None`。

### 5.3 写入

`atomic_write(path, bytes)`：

1. 临时文件为同目录 `<文件名>.tmp`；
2. 创建、写入、`flush`、`sync_all`；
3. `rename` 覆盖目标。

`save_games`：

1. `ensure_dirs`；
2. 目标存在 → `backup`（复制到 `backup/games.<ms>.json`，保留 5 份）；
3. 写 `{schemaVersion: 1, games}` 的 pretty JSON；
4. `atomic_write`。

`save_settings`：同流程，但写裸 `Settings`，备份 stem 为 `settings`。

`backup` 的失败被忽略（`let _ =`），不会阻止正式写入；备份目录不可写时只是没有新快照。

`prune_backups`：按文件名时间戳排序，删除最旧直到 ≤ 5；解析失败的时间戳记为 0。

### 5.4 pending

- `write_pending`：写裸 `Session`。
- `read_pending` / `clear_pending`：读取 / 删除。
- 启动恢复：仅 `0 < elapsed < 12h` 时累加；找不到 `gameId` 也清除。

## 6. 文件夹扫描

`scan_folder(path)`：

1. 路径不是目录 → 「请选择一个有效的文件夹」。
2. `scan_walk` 递归：
   - `depth > 6` 或结果 ≥ 500 → 停止；
   - 跳过以 `.` 开头的文件/目录；
   - 目录名（大小写不敏感）命中 `node_modules`、`$Recycle.Bin`、`System Volume Information`、`Windows`、`AppData`、`ProgramData` → 跳过；
   - 只收扩展名为 `exe` 的文件，`size` 取元数据，失败记 0。
3. 按路径小写排序，截断到 500。

不解析 Steam/Epic 库，不跟随特殊目录，不去重（前端按 `gamePathKey` 去重）。

## 7. 资源导入与路径

- `lower_ext(src)`：扩展名小写；仅接受 `png/jpg/jpeg/webp/gif/bmp`，其他一律按 `png` 处理。
- `import_cover` / `import_icon` 分别委托 `Store::import_cover` / `Store::import_icon`，共用内部图片导入实现，校验 ID、扩展名与源文件后复制到对应资源目录；使用 `create_new` 防止覆盖已有文件，写入失败清理本次文件。命名与保留策略见 [数据模型.md](数据模型.md) §3。
- `import_background` 按 main/sidebar 用途生成独立唯一文件，复制成功后对最新设置克隆候选、落盘、替换内存，最后清理对应前缀旧图；保存失败清理本次新图并保留旧引用和旧图。用途和命名见 [接口契约.md](接口契约.md) §2.5、[数据模型.md](数据模型.md) §3。
- `asset_path(kind, file)`：`background`→`backgrounds/`，`icon`→`icons/`，`superres`→`superres/`，`backgroundFit`→`background-fit/`，其他→`covers/`；只做路径拼接，不校验存在性。实际访问受 Tauri asset 协议 `$APPDATA/**` 限制。
- `open_data_dir` / `open_backups_dir`：用 `explorer <path>` 打开；备份目录不存在则先创建。

### 7.1 侧栏背景适配

`background_fit.rs` 在 `spawn_blocking` 中读取与解码原图、以 fast_image_resize 6.1.0 / Lanczos3 重采样并缓存 PNG；互斥锁限制生成并发，不占设置或游戏库锁。完整显示生成透明留空画布；铺满裁切用浮点裁框与取景位置；拉伸直接重采样。RGBA 使用缩放库的 alpha 乘除处理；按图片方向信息校正后适配。支持 PNG、JPEG、WebP、GIF 首帧和 BMP。

源文件限 64MiB、16384×16384 内且不超过 1600 万像素，解码分配预算 192MiB；先检查尺寸再完整解码。目标边长最多 4096、可视区域最多 400 万像素、单边扩展最多 512、扩展后最多 600 万像素，非法请求报错。磨砂扩边复制可视画布的边缘像素，前端按相同扩边比例显示，避免再次 cover 裁切。

输入只接受资源目录内的单个文件名，并校验 canonical 路径边界；缓存以 FNV-1a 内容摘要和全部参数及算法版本命名。缓存先限定为 PNG、匹配目标尺寸且解码分配不超过 64MiB，再完整解码校验，损坏可重建；唯一临时 PNG 成功后 rename，失败清理临时文件。仅清理本模块生成的旧缓存，按修改时间保留最多 64 份且总量不超过 128MiB，当前返回图不会被当次清理。

## 8. 封面与程序信息

### 8.1 本地封面扫描 `find_local_cover`

搜索目录：

1. 目标所在目录（目标本身是文件夹则用它）；
2. 其下 `images` / `img` / `art` / `artwork` / `cover` / `covers` 子目录（深度 1）；
3. 仅当目标目录名是中间目录（`bin` / `x64` / `win64` / `x86` / `win32` / `game` / `games` / `build`）时，才向上扩展父目录与祖父目录及其图片子目录（深度 2–4），避免把父目录的无关图片当封面。

候选过滤：

- 扩展名 `png/jpg/jpeg/webp/bmp`；
- 大小 < 10KB 直接跳过（视为图标/缩略图）。

评分：

- 强名称（`cover`、`header`、`capsule`、`poster`、`banner`、`artwork`、`keyart`、`key_art`、`boxart`、`box_art`、`封面`、`封面图`）：完全相等 `100 - 序号`，包含 `60 - 序号`；
- 弱名称（`logo`、`icon`、`title`、`tile`）：完全相等 `40 - 序号`，包含 `25 - 序号`；
- 负面词（`screenshot`、`screen`、`thumb`、`preview`、`capture`）包含则 `-25`；
- 最终 `score = name_score * 10 - depth * 5`；>200KB 额外 `+20`；≤0 丢弃；
- 取最高分，平分时先遍历到的保留。

### 8.2 系统图标 `shell_icon_png` / `icon_png`

1. `SHGetFileInfoW(SHGFI_ICON | SHGFI_LARGEICON)` 取 `HICON`；
2. `GetIconInfo` 拿颜色/掩码位图；
3. `GetObjectW` 取宽高，`GetDIBits` 以 32 位、自顶向下、`BI_RGB` 读像素；
4. BGRA → RGBA；若所有 alpha 为 0（老图标无透明通道）则全部置 255；
5. `png` crate 编码为 RGBA8；
6. 释放图标与位图句柄。

### 8.3 策略

- 图标与封面严格分开：`icon_png` 结果只写 `icons/`，不写 `covers/`；文件命名见 [数据模型.md](数据模型.md) §3。
- 自动补全时本地封面优先；没有本地封面时**保持原封面不动**，不用图标冒充。
- 版本资源：`read_version_info` 先读 `Translation` 语言/代码页，失败用 `(0x0804,0x04B0)`、`(0x0409,0x04B0)`、`(0x0409,0x04E4)`、`(0x0804,0x03A8)` 兜底；取 `ProductName`、`FileDescription`、`CompanyName`、`FileVersion`。无版本资源返回错误，调用方静默跳过。

### 8.4 `autofill`

1. 接收完整草稿与可选字段，校验目标路径存在；不查询或锁定游戏库。
2. 获取文本字段时读取版本资源（`ok()` 可选）：名称取非空 `product`，否则取 `description`；开发商取公司；备注由非空描述与 `v版本` 用「 · 」连接。有候选即替换返回草稿字段，记录到 `filled`。
3. 请求图标时提取并写入独立 PNG；请求封面时扫描本地封面并用 `Store::import_cover` 复制为独立文件。不清理或覆盖已有资源；缺少候选保留输入值。
4. 返回 `AutofillResult`；不调用 `save_games`，也不修改内存记录。图片写入失败返回中文错误，交由表单保留草稿并提示。

### 8.5 封面超分

方案与选型依据见 [调研/封面超分方案.md](调研/封面超分方案.md)，接口见 [接口契约.md](接口契约.md) §2.10。

1. **独立进程与预设**：效率档保持 Real-CUGAN `up2x-conservative`（`realcugan-ncnn-vulkan.exe -n -1 -s 2 -m models-pro -f png`）；质量档用 RealESRGAN_x4plus_anime_6B（`quality/realesrgan-ncnn-vulkan.exe -n realesrgan-x4plus-anime -s 4 -m models -f png`），原生 4× PNG 用 `image` 的 Lanczos3 缩到原图 2×后发布，与效率档同尺寸比较。两种工具使用独立工作目录和相对模型名；Windows 加 `CREATE_NO_WINDOW`，stderr 写 `superres-last.log`。取消或等待异常时 kill + wait 回收。
2. **取消与退出**：`SuperRes` 持有 `Arc<AtomicBool>`，每 100 ms 轮询；缩小和保存边界再次检查取消。任务槽保存 UUID、档位、阶段及开始时刻，提供快照；取消与清理按唯一标识匹配。退出前阻止新任务、取消并等待工作线程清理。全应用同一时刻一个任务，不排队。
3. **缓存**：游戏 id、原图 FNV-1a 64 内容哈希与预设版本组成键；效率档保持原键，质量档版本固定模型、输出倍率及缩放算法。`LookupCache::status` 只定位当前封面的候选文件并读取文件属性，不解码派生图；生成复用通过 `reusable` 完整校验，强制重建跳过复用。原图哈希与生成复用的校验结果分别由 `file_memo.rs` 在进程内按路径、文件长度、修改时间及可用的创建时间记忆，各最多 128 项、按最近使用淘汰。文件变化、删除或读取期间变化时不复用旧结果；不缓存文件缺失。`superres_status` 在 `spawn_blocking` 中读取文件与属性，以独立缓存锁合并重复工作，不占游戏库或任务锁。显示失败及重新生成的调用约定见[接口契约.md](接口契约.md) §2.10。同目录直接 rename 替换，失败保留旧缓存。缓存命中不启动进程。
4. **发布**：推理和缩小使用临时 PNG；验证输出可解码、尺寸正确、原封面内容未改变且未取消才发布；临时文件守卫负责失败/取消清理。终态事件前释放任务槽。
5. **进度**：只发真实 `processing` / `resizing` / `saving` 阶段与已用时间，不伪造总百分比。
6. **分发**：效率档资源保持原路径；质量档只将程序、所需 DLL 和单个 anime6B 模型放在 `binaries/superres/quality/`。许可及来源随资源打包。`sidecar_dir` 按档位先找资源目录，再退回开发路径，统一处理 verbatim 前缀。
7. **边界**：无 CPU 回退开关（CUGAN 支持 `-g -1`，Real-ESRGAN 工具需要 Vulkan）；删除游戏记录不清理派生图。仍为单张串行任务，不扩展批量。

> 踩坑记录：Tauri 的 `resource_dir()` 返回 `\\?\D:\...` 形式的 verbatim 路径。Real-CUGAN 不认这种写法，会把 `-m` 的绝对路径原样拼到 exe 目录后面（日志里表现为 `exe目录\?\D:\...\models-pro/up2x-conservative.param`），`_wfopen` 失败后直接 `abort`（0xc0000409）。现在 `sidecar_dir` 统一去掉 `\\?\` 前缀，`-m` 固定传相对目录 `models-pro`；子进程 stderr 写入 `superres/superres-last.log`，失败时取末尾 300 字附在错误里。

## 9. 联网元数据

### 9.1 通用

- `reqwest::Client`：20 秒超时，UA 为 `WhaleDeck/0.3 (local game library; https://github.com/shasha111250/whaledeck)`。
- 错误映射：超时「…连接超时，请检查网络后重试」；连接失败「…无法连接，可能是网络或代理问题」；其他「…请求失败：…」；非 2xx 返回「…返回 HTTP 状态」。
- `percent_encode` 只保留字母数字与 `-_.~`，空格编码 `%20`，其余 `%XX`。

### 9.2 Bangumi

- `POST https://api.bgm.tv/v0/search/subjects`
- body：`{ keyword, filter: { type: [4] }, limit: 10 }`（type 4 = 游戏）
- 解析 `data[]`：`id`、`name` / `name_cn`（优先中文）、`images.large`、`date`、`summary`、`rating.score`；`subtitle` 在中文名与原名不同时保存原名。

### 9.3 VNDB

- `POST https://api.vndb.org/kana/vn`
- body：`filters: ["search", "=", keyword]`，字段 `id,title,alttitle,image.url,released,rating,description,developers.name`，`results: 10`
- 解析 `results[]`：标题、别名、封面、发售日、评分、简介、开发商（多个用「、」连接）。

### 9.4 月幕

- token：`GET https://www.ymgal.games/oauth/token?grant_type=client_credentials&client_id=ymgal&client_secret=luna0327&scope=public`
- token 缓存在进程内 `Mutex<Option<(String, Instant)>>`，有效期 50 分钟。
- 搜索：`GET https://www.ymgal.games/open/archive/search-game?mode=list&keyword=<编码>&pageNum=1&pageSize=10`
- 请求头：`Accept: application/json;charset=utf-8`、`Authorization: Bearer <token>`、`version: 1`
- 解析 `data.result[]`：`id`、`name` / `chineseName`（优先中文）、`mainImg`、`releaseDate`、`orgName`、`score`（字符串转数字，≤0 视为无评分）；月幕不返回简介。
- `success === false` → 使用返回的 `msg` 拼错误。

### 9.5 图片下载

- 只允许 HTTPS 且以 `https://lain.bgm.tv/`、`https://t.vndb.org/`、`https://cdn.ymgal.games/` 开头。
- 按 `Content-Type` 决定扩展名：png / webp / gif，否则 jpg。
- 读取完整响应后检查 ≤ 12MB，超限报错。
- `apply_meta` 下载成功后写独立封面文件（命名见数据模型），保留原图，再更新候选字段；新封面取景重置，落盘成功才替换内存。

## 10. 存档备份

### 10.1 备份

1. 收集 `save_paths` 的 trim 非空项；为空 → 「还没有设置存档目录，先在「编辑」里添加」。
2. 创建 `backups/<gameId>/`；文件名 `<createdAt 毫秒>.zip`。
3. 先写 `manifest.json`：`{ version: 1, sources }`。
4. 逐目录递归写入，前缀为目录下标（`0/...`、`1/...`）；空目录跳过；文件数累加。
5. 任一步失败或文件数为 0 → 删除 zip 并返回错误。
6. 返回 `SaveBackup { file, created_at, size }`。

### 10.2 列表

只接受文件名为「纯数字 + `.zip`」的条目，按 `created_at` 倒序；大小取元数据。

### 10.3 还原

1. 文件名含 `/`、`\`、`..` → 拒绝。
2. 文件必须存在于 `backups/<gameId>/`。
3. 读取 `manifest.json`；缺失/损坏 → 报错。
4. 遍历 zip 条目：
   - 跳过 `manifest.json` 与目录条目；
   - 必须能拆成 `<index>/<rel>`，`index` 在 `sources` 范围内；
   - `safe_relative(rel)`：非空、不含 `..`、不含 `:`、不以 `/` 或 `\` 开头；
   - 目标为 `sources[index] / rel`，创建父目录，覆盖写入。
5. 写入数为 0 → 「这个备份里没有可还原的文件」，否则返回数量。

还原不删除目标目录中的多余文件，也不做整体原子替换；中途失败可能留下部分文件。

## 11. 整库导出/导入

- `BackupFile { schema_version, games, settings }`；读取时 `schema_version` 默认 0，但不校验。
- 导出：保存对话框取消 → `false`；写 pretty JSON；把 `covers/` 顶层文件复制到同级 `<stem>.covers/`（不递归、忽略错误）。
- 导入：打开对话框取消 → `0`；解析失败报「备份格式不正确」；整体替换 `games`/`settings` 并分别写盘；复制 `<stem>.covers/` 到 `covers/`；返回游戏数。
- 不导入图标、背景、存档 zip；不清理旧资源。

## 13. 已知边界（后端）

1. pending 只有一个文件，多进程目标同时运行时后写覆盖先写；任一结算会清除它。
2. 启动恢复只补算一次，且 12 小时以上视为异常丢弃。
3. `delete_game` / `reset_playtime` 在写盘失败时内存已变化，可能与磁盘不一致。
4. 监控结算写盘失败仍会移除会话并清 pending，事件中的时长可能未落盘。
5. `is_running` 按进程名匹配可能误判（同名程序）；PID 复用未校验启动时间。
6. 同一路径可被重复加入；去重只在前端批量加入时做。
7. 整库导入不校验 `schemaVersion`，不清理旧图标/背景/存档。
8. 存档还原非原子，失败可能留下部分文件；不删除多余文件。
9. 月幕使用公开的 client_id/secret（第三方公共凭据），有速率限制，失败不自动重试。
10. `asset_path` 只拼路径，不做目录穿越校验；安全边界依赖 Tauri asset 协议 scope。
11. 删除记录不清理封面/图标/备份文件，磁盘会保留孤儿资源。
